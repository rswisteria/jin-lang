## この分野で既に知っていること（推測）
- 一般的なプログラミング（変数・関数・if・ループ・リスト・構造体）を使える — 既存マニュアルの想定読者に揃えた
- JSON を読み書きできる — `.jin` は JSON で、既存マニュアルも前提にしている
- ゲームループ（毎フレーム更新して描く）の考え方は、聞けば分かる — v2 の例がゲーム中心なので
- Jin v1（LLM エージェント）は知らない、または知っていても v2 とは別物と思っている — v2 は汎用ビジュアル言語で語彙が違う

## 怪しいところ（推測。資料の芯になる）
- 「陣（circle）・手順（rite）・記憶（state）・道具（sigil）」の対応が、関数・変数・ライブラリのどれに当たるかが分からない
- tick（1 フレーム）と `wait` の関係。手順が tick をまたいで止まる・再開する、という実行の形は普通の言語に無い
- 他の陣の公開 state（`out`）が「前の tick の確定値」で読めること（二重バッファ）
- 能力（`canvas.rect` など）が effect / read / state に分かれていて、式の中で呼べるものと `cast` でしか呼べないものがあること
- 1 陣に 12 個まで、手順の直下のステップは 12 個まで、という上限が設計上の約束であること
- 書いた `.jin` が、魔法陣の図・完全陣（1 枚の絵）・鑑賞ページの 3D と、同じものの別の見え方であること
