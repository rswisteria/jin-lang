# テトリスを作りながらプログラミングを学ぶ — Jin v2 入門チュートリアル

[← README に戻る](../README.md) ／ [利用ガイド（v1・AI エージェント）](usage.md) ／ [完成形 `examples-v2/tetris/tetris.jin`](../examples-v2/tetris/tetris.jin)

このチュートリアルは、**WebフロントエンドやWeb制作の経験を持つエンジニア**が、ビジュアル言語「Jin v2」の言語仕様を基礎から体系的に理解し、**テトリスをゼロから実装できるようになる**までの道のりを 9 段階で案内します。

プログラミングとゲーム開発の核となる概念 —— **状態（変数）、型、条件分岐、ループ、関数、配列（リスト）、構造体（オブジェクト）、イベント、シーン管理、デバッグ** —— を、テトリスの機能を組み立てる過程で順番に手に入れていきます。

各段階には「実際に動く `.jin` ファイル」が用意されており、エディタで直接動かして動作を確認しながら、**「なぜその仕組みが必要なのか」をゲームの課題として先に体感してから新しい言語仕様を学ぶ（Progressive Disclosure: 段階的開示）** 構成になっています。

## 対象読者と前提知識

- **対象読者**:
  - HTML/CSS/JavaScript などの基礎知識があり、新しい言語仕様やゲームプログラミングの仕組みを学びたい Web エンジニア
  - プログラミングの基礎構造（変数・制御構文・データ構造・関数設計）を、ゲーム制作を通じて実践的にマスターしたい方
  - ビジュアル言語 Jin v2 の宣言的なアーキテクチャと設計思想を理解したい方
- **前提知識**:
  - ターミナルで基本的なコマンド（`cd`, `uv` など）を実行できること
  - [README のセットアップ](../README.md#エディタの実行方法)（`uv` / `pnpm`）を済ませて、`uv run jin editor …` でエディタが起動できること
- **数学の前提知識**:
  - 四則演算（`+`, `-`, `*`, `/`）と割り算の余り（`%`）のみ。高度な数学や物理演算は不要です。

> [!NOTE]
> Jin v2 はビジュアル言語で、プログラムはエディタ上で「魔法陣」の図として表現されます（ファイルの実体は宣言的な JSON ですが、本チュートリアルで JSON を読み書きすることはありません）。
> Web開発における「HTML `<canvas>` の描画」「コンポーネント構造」「ステート管理（State）」「イベントリスナー」に近いメンタルモデルを持つため、Webエンジニアなら直感的に構造を理解できます。本チュートリアルのコード例は、**`jin render` が描いた手順の図**と、**その手順の各ステップをエディタで選んだときに右パネルに出る内容の一覧**の組で示します。

## 学び方

各段階は、次の 4 つのステップで進めます。

1. **開いて遊ぶ（実行モード）**:
   - `uv run jin editor docs/samples/tetris/<番号>-<名前>.jin` でビジュアルエディタが起動します。
   - 上部メニューの **「実行」** をクリックすると、右側に黒い実行パネルが現れてゲームが動き始めます（ゲーム画面を一度クリックしてフォーカスを当ててからキーを押してください）。
2. **図とコードを読む（編集モード）**:
   - 上部メニューの **「編集」** をクリックすると、魔法陣の図面編集モードに切り替わります。
   - 魔法陣の手順環には手順（`rite`）が**頭文字の印**（`paint` なら `P`）で並び、中央には核の手順名が表示されます。
   - 印を 1 回クリックすると右パネルに手順名が表示され、**ダブルクリックするとその手順の内部ステップの図**（ステップが輪になって並ぶ展開ビュー）に切り替わります。元の図に戻るには上部の **「focus を外す」** を押します。本文の図と一覧は、この展開ビューと右パネルに対応しています。見比べてみてください。
3. **書き換えて試す（ホットリロード & 保存）**:
   - 「編集」モードでステップをクリックすると、右パネルに `Do` / `Target` / `Args` / `Expr` などのプロパティ入力欄が現れます。
   - 数値や式を書き換えて `Enter` を押すと確定します。「実行」モードに切り替えると、走っている途中の状態を保ったまま即座に変更が反映されます（「編集しても状態を保つ」が既定で有効です）。
   - ファイルに保存するには、上部の **「保存」** ボタンを押します（「保存しました: …」と通知されます）。
4. **練習問題で定着させる**:
   - 各節の末尾に課題を用意しています。エディタ上で実際に書き換えて挙動の変化を確かめてみましょう。

ターミナルから画面を表示せずに直接走らせる（ヘッドレス実行）ことも可能です：

```bash
uv run jin run docs/samples/tetris/01-canvas.jin --ticks 60
```

## 0. 準備 — プログラムが動く仕組み

### 0-1. 動かす

README のセットアップが済んでいれば、次の 2 行で第 1 段階が開きます（プレイヤーのビルドは v2 のゲーム描画エンジンを生成するために必要です）。

```bash
cd apps/player && pnpm install --frozen-lockfile && pnpm build && cd ../..
uv run jin editor docs/samples/tetris/01-canvas.jin
```

ブラウザに魔法陣が出れば準備完了です。上部の「実行」を押すと、右側に黒い画面（実行パネル）が出てゲームが動き始めます。図に戻って直すときは「編集」を押します。

### 0-2. 3 つの言葉

Jin v2 のプログラムは、3 種類の基本要素で構成されています。Webフロントエンドの概念と対比しながら覚えておきましょう。

| Jin の言葉 | Web開発・プログラミングでの概念 | 本教材での役割 |
|---|---|---|
| **舞台**（`stage`） | `<canvas>` 画面と描画ループ | 176 × 176 ピクセルのゲーム画面。1 秒間に 30 回再描画（`fps: 30`） |
| **陣**（`circle`） | コンポーネント / シーン（場面） | ゲームの 1 場面（タイトル、プレイ画面、ゲームオーバー等）。独自の状態・手順・道具を持つ |
| **手順**（`rite`） | 関数 / メソッド | ステップ（命令オブジェクト）の配列。名前をつけて呼び出せる |

陣（`circle`）の内部は、同心円状の **4 つの環（Rings）** に分かれています。エディタの魔法陣では内側から順に描かれています。

1. **記憶環**（`state`）: 変数の定義。コンポーネントのローカル State に相当
2. **道具環**（`sigils`）: 画面描画や入力などの外部機能（API・ライブラリ）の利用宣言
3. **手順環**（`rites`）: 実行ロジック（関数群）の定義
4. **境界環**（`boundary`）: イベントリスナー（`on tick` など）や不変条件チェック（`guards`）の定義

### 0-3. tick — プログラムの時間

ゲームは「1 秒間に 30 回、同じ更新・描画処理を繰り返す」ことで動作します。この 1 コマの時間を **tick** と呼びます。30 fps（フレーム/秒）の場合、1 tick は 1/30 秒（約 33.3 ミリ秒）であり、30 tick で 1 秒が経過します。

- **核**（`core`）: 陣が開始（マウント）されたときに **1 回だけ** 呼ばれる主手順です。時間を進めたりループを回したりします。**核の手順が最後まで実行されても、陣自体は終了しません**。陣を明示的に終了させるのは **`finish`** ステップです
- **`on tick`**: 境界環に登録し、**毎 tick** 自動的に呼び出されるイベントハンドラです。画面の再描画（レンダリング）はここで行います

「**核で時間を進め、`on tick` で毎フレーム描画する**」。これが Jin によるゲーム開発の基本アーキテクチャです。

## 1. 舞台に描く

**ファイル**: [`docs/samples/tetris/01-canvas.jin`](samples/tetris/01-canvas.jin)

エディタで開くと、暗い背景に灰色の枠、その中に黒い盤面、そして左上寄りに水色のマスが 1 つ描かれます。10 秒（300 tick）経過すると画面が止まります。

### 1-1. 座標

画面の左上が原点 `(0, 0)` です。右へ進むほど x が増加し、**下へ進むほど y が増加します**（HTML の Canvas API や CSS の絶対配置と同じ座標系です）。

テトリスの盤面は横 10 マス × 縦 20 マスで構成されます。1 マスを 8 × 8 ピクセルとし、盤面の左上基点を `(8, 8)` に配置します。

- 列 `c`（0〜9）、行 `r`（0〜19）のマス左上座標: `(8 + c * 8, 8 + r * 8)`
- 描画サイズ: 7 × 7 ピクセル（1 ピクセルの隙間を空けることでマス目のグリッドを表現）

### 1-2. 呼び出し（`cast`）

画面への描画は、道具環で宣言した `canvas`（画面描画機能）を呼び出して行います。操作を呼び出す命令が **`cast`** ステップです。手順 `paint` の図と、ステップの一覧です。まず末尾の 6 と 7 を見てみましょう。

> [!TIP]
> **図の読み方**（以後の章でも同じです）
> - 中央の円が手順の名前、外側の環に**手順直下のステップ**が並びます。番号は上（12 時の位置）から**時計回り**です
> - `if` や `loop` の中身は、親の弧の内側の環に置かれます。番号は `2.1`（2 番の `loop` の中の 1 番目）、`4t1`（4 番の `if` の then 側の 1 番目）、`4e1`（else 側）のように読みます。図では then が親の弧の前半（反時計回り側）、else が後半です
> - 「記号」列は図の中の形です（`set` は四角、`let` は小さな四角、`cast` は円、`if` は弦、`loop` は多角形、`wait` は環の欠け、`return` / `finish` / `break` は外へ抜ける線）。矢印は実行の順です
> - 「Do」と「内容」は、エディタでそのステップを選ぶと右パネルに出る欄（`Do` / `Target` / `Args` / `Cond` …）をまとめたものです

- **Do = `cast`**: 操作や関数を呼び出すステップです
- **Target**: 呼び出し先です。`canvas.ink` は描画色の指定、`canvas.rect` は塗りつぶし矩形の描画です
- **Args**: 渡す引数の並びです。**要素はすべて「式」として評価されます**。そのため `8 + 3 * 8` と書くと、式が計算されて `32` として渡されます。これは列 3・行 0 のマス、すなわち `(32, 8)` の位置です
- 色の指定は `"#4ce0e6"` のような文字列です。式の中の文字列は二重引用符で囲みます（エディタの `Args` の欄にそのまま `"#4ce0e6"` と入力します）

手順 `paint` の先頭では `canvas.clear` で画面全体を背景色で塗りつぶし、枠線と黒い盤面を描画しています。**画面は tick ごとに初期化（白紙化）される**ため、表示し続けたい要素は毎 tick 描き直す必要があります。そのため `paint` は `on tick` に登録されています。

### 1-3. 核の手順と `wait`

核の手順 `begin` は、2 つのステップだけで構成されています。

<!-- figure: 01-canvas Play/begin -->
<!-- 生成物（scripts/generate_tutorial_figures.py）。手で編集しない -->
<img src="images/tutorial/01-canvas-Play-begin.svg" width="360" alt="手順 begin の図">

| 番号 | 記号 | Do | 内容 |
|---|---|---|---|
| 1 | 環の欠け | `wait` | `300` tick 待つ |
| 2 | 外へ抜ける線（二重横棒） | `finish` | 陣を終える |
<!-- /figure -->

- **`wait`**: 指定した tick 数だけ処理を一時停止（スリープ）します。図では環の欠けとして描かれます
- **`finish`**: 現在の陣を終了します。図では環の外へ抜ける線（先端に二重横棒）です

`begin` は 300 tick（10 秒）待機した後に `finish` を実行します。この陣は root（最外の親）であるため、陣の終了に伴いゲーム全体が停止し、`on tick` の描画も止まります。10 秒で画面が停止するのはこの仕組みによるものです。

もし `finish` ステップを削除するとどうなるでしょうか？ 核の手順自体は 10 秒で最後まで到達して終了しますが、**陣そのものは生き続けるため、`on tick` の `paint` は毎フレーム呼ばれ続けます**。「核の手順の終了」と「陣の終了」は明確に分離されており、陣を閉じるには必ず `finish` が必要です。

### 練習問題

1. マスの色を黄色（`#f2d541`）に変えてみましょう。「編集」モードで手順環の P（`paint`）をダブルクリック → 色設定ステップ（`canvas.ink`）を選択 → 右パネルの `Args` を書き換えて Enter → 「保存」→「実行」で確認します
2. マスを盤面の右下（列 9・行 19）に配置してください。座標の計算式を書いて狙い通りの位置に描画されるか確認しましょう
3. `wait` の tick 数を 60（2 秒）に変更し、停止するまでの時間が短くなることを確認してください
4. `finish` ステップを削除し、指定 tick を過ぎても描画が停止しなくなる挙動を確かめてみましょう（ステップを選択して Delete キーで削除できます）

## 2. 記憶と時間 — マスを落とす

**ファイル**: [`docs/samples/tetris/02-fall.jin`](samples/tetris/02-fall.jin)

マスが 0.5 秒（15 tick）ごとに 1 段ずつ下へ落ち、盤面の底（行 19）に着くと 1 秒後に停止します。

### 2-1. 記憶環（変数）

第 1 段階では、マスの座標を `3` と `0` という固定値で直接記述していました。マスを動かすためには、「現在どこにいるか」という状態を保持する場所が必要です。それが記憶環の **`state`**（変数）です。

<!-- /figure -->

- **名前**: 変数名です
- **型**: 変数の**型**です。`num`（数値）のほか、`bool`（真偽値）、`str`（文字列）、`list<...>`（配列）などがあります。静的型付けにより、数値用の変数に誤って文字列を代入するようなバグは、実行前の静的検査（`jin check`）が検知します
- **最初の値**（`init`）: 初期値の式です
- **out**（`out: true`）: 外部公開フラグです。他の陣から値を参照できるようになり、`jin run` の終了ログやデバッグ用の値一覧パネルに表示されます

変数 `x`, `y` を導入したことで、`paint` 内の描画座標の式は `"8 + x * 8"`, `"8 + y * 8"` に置き換わりました。変数の値が更新されると、描画される位置も連動して変化します。

### 2-2. `set` と `loop while` と `wait`

核の手順 `begin` で時間を刻み、落下処理を実行します。

<!-- 生成物（scripts/generate_tutorial_figures.py）。手で編集しない -->
<img src="images/tutorial/02-fall-Play-begin.svg" width="360" alt="手順 begin の図">

| 番号 | 記号 | Do | 内容 |
|---|---|---|---|
| 1 | 四角 | `set` | `y ← 0` |
| 2 | 多角形（3 角） | `loop` | `y < 19` の間、中を繰り返す |

| 4 | 外へ抜ける線（二重横棒） | `finish` | 陣を終える |
<!-- /figure -->

各ステップの実行フローは次の通りです：

1. **`set`**（代入）: `y` に `0` を代入します
2. **`loop while`**（条件付き繰り返し）: 条件式 `y < 19` が真である間、内側の環にある 2.1 と 2.2 を繰り返します
   - 2.1 `wait`: 15 tick（0.5 秒）待機します
   - 2.2 `set`: `y` の値を 1 増加させます。右辺の式 `y + 1` が先に評価され、その結果が左辺の `y` に再格納されます
3. `y` が 19 に達するとループを抜け、30 tick（1 秒）待機した後に **`finish`** で陣を終了します

ここで重要なのは、**`begin` が `wait` で待機している間も、`on tick` に登録された `paint` は毎フレーム（毎 tick）呼び出されている**という点です。核の手順は「座標を更新して休止する」ことに専念し、描画手順は「その時点の最新の座標を描く」ことに専念しています。ロジックと描画が疎結合に保たれているため、コードが簡潔で見通しの良い状態を維持できます。

## 3. 入力と分岐 — キーで動かす

### 3-2. `pressed` と `key` の違い

ユーザー入力を取得する API には、用途に応じて 2 種類のメソッドが用意されています。

- `input.pressed("ArrowLeft")`: **キーが押された瞬間の 1 tick だけ** `true` になります。押しっぱなしにしても最初の 1 回しか反応しません。1 回の押下で 1 マスだけ移動させたい操作に適しています
- `input.key("ArrowDown")`: **キーが押されている間、毎 tick 連続して** `true` になります。押しっぱなしによる高速落下（ソフトドロップ）に適しています

キー名は Web 標準の `KeyboardEvent.code` に準拠しています（`ArrowLeft`, `ArrowRight`, `ArrowUp`, `ArrowDown`, `Space`, `KeyA` など）。存在しないキー名を指定すると、エディタ上でエラーとして強調表示されます。

### 3-3. 手順から手順を呼ぶ

手順 `control` の末尾（4 番）にある `cast` の `paint()` に注目してください。図では、道具を呼ぶ `cast` の円が環の**外**へ短い線を出すのに対し、自陣の手順を呼ぶ `cast` の円は**内**へ線を出します。**自陣の中で定義された他の手順も、`cast` ステップによって関数として呼び出すことができます**。「入力判定と状態更新」と「画面描画」を別々の手順に責任分離したまま、1 tick の中で順序立てて実行しています。

また、核の手順 `begin` は `loop while true`（無限ループ）に改修され、マスが底に着いたときは `else` 節で `y` を 0 にリセットして再スタートするように構成されています。

## 4. 型紙と表 — 7 種のミノ

**ファイル**: [`docs/samples/tetris/04-piece.jin`](samples/tetris/04-piece.jin)

単一のマスから、7 種類のテトリミノ（I, O, T, S, Z, J, L）へと進化します。それぞれの固有色で落下し、↑ キーで 90 度回転します。底に着くと、次のミノがランダムに生成されます。

なお、この段階では意図的に**左右の壁の当たり判定を省略**しています。← キーを押し続けると画面左外へ突き抜けますが、これは第 5 段階で解決します。

### 4-1. 型紙（構造体） — まとまった値

ミノの状態を管理するには、「種類（`kind`）」「向き（`rot`）」「位置 x（`x`）」「位置 y（`y`）」という 4 つの値が必要です。これらを個別の変数として定義する代わりに、**型紙**（`form`）を用いて 1 つの複合データ型にまとめます（TypeScript の `interface` や C 言語の構造体に相当します）。

| 欄 | 型 |

記憶環の変数 `piece` はこの `Piece` 型として定義され、初期値は `Piece{kind: 0, rot: 0, x: 3, y: 0}` というリテラル記法で代入します。各プロパティには `piece.x` のように**ドット演算子**でアクセスでき、`set` の `target` に `piece.y` と指定することで、特定のフィールドだけを直接更新できます。

### 4-2. 表 — 形をリストに入れる

7 種類 × 4 方向のブロック形状を、28 個の `if` 文で分岐させて描画するのは極めて非効率です。そこで、**すべての形状データを 1 本のフラットな数値配列に格納し、添字（インデックス）計算によって必要な座標を取り出すテーブル引き**（ルックアップテーブル）を採用します。これが変数 `shapes`（型 `list<num>`）です。

配列内のデータ配置規則は次の通りです：

- テトリミノは 4 つの正方形ブロックで構成されます。各ブロックの相対座標 `(cx, cy)` を 2 つの数値ペアで表現します
- 1 つの向きの形状 = 4 ブロック × 2 数値 = **8 個の数値**
- 1 種類のミノ = 4 方向 × 8 数値 = **32 個の数値**
- 7 種類のミノ全体 = 7 種類 × 32 数値 = **224 個の数値**

ミノの種類 `kind`（0〜6）、向き `rot`（0〜3）、何番目のブロックか `i`（0〜3）から、配列内のインデックスを求める計算式は次のようになります：

```
((kind * 4 + rot) * 4 + i) * 2        ← x の添字
((kind * 4 + rot) * 4 + i) * 2 + 1    ← y の添字
```

例えば、T 型ミノ（`kind = 2`）の向き 1 における 3 番目のブロック（`i = 2`）の x 座標は、`((2 * 4 + 1) * 4 + 2) * 2 = 76` 番目、y 座標は 77 番目となります。配列は **0 始まり（ゼロインデックス）** です。同様に色データも `colors`（`list<str>`）に 7 色定義され、`colors[kind]` で高速に取り出せます。

### 4-4. 乱数と剰余

ミノの新規出現を行う手順 `spawn` では、道具環の `random` を使用して `Piece{kind: random.range(0, 6), rot: 0, x: 3, y: 0}` を生成しています。`random.range(0, 6)` は **0 以上 6 以下** の整数をランダムに返します（最小値・最大値の両端を含みます）。

↑ キーによる回転処理は、`(piece.rot + 1) % 4` という式で更新されます。`%` は割り算の**余り（剰余演算子）** です。向きが 0 → 1 → 2 → 3 と進み、3 の次は `(3 + 1) % 4 = 0` に戻ります。「N で割った余り」は、限られた範囲の数値を循環させるプログラミングの典型的な手法です。

乱数生成器の種（シード）は `stage.seed`（このファイルでは 3）によって決定論的に固定されています。**シード値が同一であれば常にまったく同じ順序でミノが出現する**ため、不具合の調査や自動テストの再現性を 100% 担保できます。

### 練習問題

1. 回転の方向を反時計回りに変更してください（`+ 1` の代わりに何を足して `% 4` を取れば 1 つ前の向きに戻せますか？ ヒント: `+ 3`）
2. 最初に生成されるミノを常に I 型（`kind: 0`）に固定してみてください
3. `shapes` の先頭 8 個の数値 `0, 1, 1, 1, 2, 1, 3, 1` は I 型ミノの向き 0 を表しています。各マスの相対位置を方眼紙にプロットし、どのような形状か確認してください

## 5. 当たり判定 — 手順に名前をつける

**ファイル**: [`docs/samples/tetris/05-fits.jin`](samples/tetris/05-fits.jin)

左右の壁を突き抜けなくなりました。また、壁際で回転したときにブロックが壁にめり込む場合は、回転が無効化されます。

### 5-1. 同じ検査を 4 か所でしたい

第 4 段階では「底に着いたか」の検査しか実装されておらず、左右移動や回転は無制限に行われていました。正しくは、**位置や向きを更新する前に、「動かした先が盤面内に収まっているか」を事前に検証する** 必要があります。

この判定は「左移動」「右移動」「回転」「自然落下」の **4 か所すべてで実行** されなければなりません。同じ検証コードを 4 回コピペすると、修正漏れによるバグの温床になります。そこで、**判定ロジックを引数と戻り値を持つ 1 つの手順として独立させ、必要な場所から呼び出します**。これがプログラミングにおける「関数」の基本原則です。

<!-- 生成物（scripts/generate_tutorial_figures.py）。手で編集しない -->
<img src="images/tutorial/05-fits-Play-fits.svg" width="360" alt="手順 fits の図">

手順 `fits(kind: num, rot: num, x: num, y: num) -> bool`

| 番号 | 記号 | Do | 内容 |
|---|---|---|---|
| 1 | 多角形（3 角） | `loop` | `4` 回、中を繰り返す（`i` に 0, 1, … が入る） |
| 1.1 | 小さな四角 | `let` | `cx = x + shapes[((kind * 4 + rot) * 4 + i) * 2]` |
| 1.2 | 小さな四角 | `let` | `cy = y + shapes[((kind * 4 + rot) * 4 + i) * 2 + 1]` |
| 1.3 | 弦（分岐） | `if` | `cx < 0 or cx >= 10 or cy >= 20` が真なら t の列へ |

| 2 | 外へ抜ける線 | `return` | 手順を抜けて `true` を返す |

- **引数**（`params`）: 手順の見出し `fits(kind: num, rot: num, x: num, y: num) -> bool` の括弧の中が、受け取る引数の名前と型です
- **純粋な判定**: `fits` は現在の変数 `piece` を直接参照せず、渡された引数 `(kind, rot, x, y)` に基づいて計算します。これにより、「もし 1 マス左に動かしたら？」「もし回転させたら？」という **未来の仮想的な位置** を、状態を書き換える前に安全に問い合わせることができます
- **早期リターン（Early Return）**: `cx < 0 or cx >= 10 or cy >= 20`（左壁外、右壁外、床下）のいずれかに該当した時点で、即座に `return false` を実行して手順を終了します。4 つのブロックがすべて境界内に収まっていれば、ループ完了後に末尾の `return true` が返されます

3. `ok` が真であれば、実際に `piece.x` を更新する

右移動、回転、落下もまったく同じ「事前に安全を確認してから状態を更新する」パターンで統一されています。

### 5-3. 手順を分ける理由 — Jin の 3 つの上限

Jin には、コードの品質と可読性を保つために意図的に設定された **3 つの厳格な上限ルール** が存在します。これに違反すると静的検査で警告やエラーが出力されます。

| 上限ルール | 診断コード | 理由と設計思想 |
|---|---|---|
| 1 つの手順直下のステップ数は **最大 12 個** まで | JIN210 | 1 つの手順が長大化すると可読性が著しく低下するため、小さな手順に責務分割させる |
| `if` や `loop` のネスト（入れ子）は **最大 3 段** まで | JIN211 | 深い入れ子は認知負荷を高めてバグの原因となるため、内側の処理を別手順に切り出させる |
| 手順内の局所変数名は **重複不可**、`state` と同名も禁止 | JIN010 | 変数のシャドーイング（隠蔽）による混乱を未然に防ぐ |

「ステップ数が 12 個を超えそう」「4 段階目のネストが必要になった」という状況は、**新しい手順を切り出すべきリファクタリングの合図** です。

また、戻り値（`returns`）を宣言した手順では、すべての分岐の末尾で必ず `return` ステップに到達するように記述しなければなりません（`fits` 末尾の `return true` がこれに該当します）。

## 6. 盤面はリスト — 積もる

**ファイル**: [`docs/samples/tetris/06-board.jin`](samples/tetris/06-board.jin)

落下したミノが底や他のブロックに着地すると固定（ロック）され、次のミノが出現します。ブロックが上端まで積み上がるとゲームオーバーとなり停止します。

### 6-1. 200 個の数

盤面は横 10 × 縦 20 ＝ 200 マスあります。各マスが「空（`0`）」か「何色のブロックが置かれているか（`1`〜`7`）」を記録する必要があります。200 個の変数を個別に定義する代わりに、**200 要素の 1 本のリスト** `board`（型 `list<num>`）で一括管理します。

- 行 `r`・列 `c` のマスに対応するインデックス: `r * 10 + c`
- 逆にインデックス `i` から行と列を逆算する式: 行は `floor(i / 10)`（小数点以下切り捨ての商）、列は `i % 10`（余り）

### 6-2. 固定する — 添字への代入

着地して動けなくなったミノのブロックを、盤面配列に転記して固定するのが手順 `lock` です。

```

```

### 6-3. 終わりを決める

新しいミノを生成する `spawn` では、生成直後に `fits` を呼び出します。出現位置にすでにブロックが存在して収まらない場合、盤面がいっぱいになったと判断して変数 `over` を `true` に設定します。

核のメインループは `loop while not over` としてあるため、`over` が真になった瞬間にループを抜けて `finish` が実行されます。また、入力手順 `control` の先頭にも `if over then return` を配置し、終了後のキー操作を遮断します。

## 7. 行を消す — 入れ子の繰り返し

**ファイル**: [`docs/samples/tetris/07-lines.jin`](samples/tetris/07-lines.jin)

横一列がブロックで揃うとその行が消滅し、上のブロック群が 1 段落下します。同時に SCORE（得点）と LINES（消した行数）が加算され、5 行消すごとに落下速度がアップします。

### 7-1. アルゴリズムを言葉で書く

複雑なアルゴリズムを実装する際は、コードを書く前に日本語で手順を整理します。

1. 最上行から最下行に向かって順に各行を検査する：
   1. 行内の 10 マスを走査し、空マス（`0`）が 1 つでもあれば「揃っていない」と判定する
   2. 10 マスすべてが埋まっていれば、その行より上にあるすべての行を 1 段下へシフトし、最上行を空（`0`）にする。消去行カウントを 1 増やす
2. 消去した行数が 1 以上であれば、行数に応じた得点を加算し、落下速度を更新する

これをコード化したのが手順 `clearLines` です。

| 2.3 | 弦（分岐） | `if` | `full` が真なら t の列へ |

| 3t2 | 四角 | `set` | `score ← score + bonus[cleared]` |

この実装には 3 つの重要な設計技法が含まれています：

1. **論理の反転フラグ**: 「すべてのマスが埋まっているか」を判定するために、初期値を `full = true` とし、空マス（`0`）を 1 つでも発見したら `full = false` に倒すパターンを採用しています
2. **シフト処理の逆順走査**: 上のブロックを 1 段下（インデックス `+ 10`）へ複製する際、`i = r * 10 - 1 - k` として**下から上に向かって逆順にコピー** しています。上から順にコピーすると、直前にコピーした値が次の複製の読み出し元になってしまい、同じ行が下まで複製される「破壊的データ上書き」が発生するためです
3. **ネスト 3 段制限の遵守**: `r` のループ（1 段目） → `if full`（2 段目） → `k` のループ（3 段目）と、Jin のネスト上限（3 段）を厳格に守っています。また、JIN010 ルールに従い、列ループのカウンタ変数名も `c` と `c2` で重複を回避しています

### 7-2. 表引きと速さ

消去した行数に応じた得点計算には、多段の `if` 文ではなく配列によるテーブル引き（ルックアップテーブル）を利用します。

```
let bonus = [0, 100, 300, 500, 800]
score = score + bonus[cleared]
```

1 行消去なら 100 点、2 行なら 300 点、4 行（テトリス）なら 800 点が加算されます。

また、落下間隔（フレーム数）は次の式で動的に算出されます：

```
speed = max(4, 15 - floor(lines / 5))
```

5 行消去するごとに `speed` が 1 tick ずつ短縮され、最短でも 4 tick（限界速度）より速くはならないよう `max` 関数で下限を保証しています。核の `wait` で使用する値を固定値の `15` から変数 `speed` に切り替えることで、ゲームの進行に応じた難易度上昇が実現されています。

### 練習問題

1. 得点テーブルを初代テトリス仕様（`[0, 40, 100, 300, 1200]`）に変更してください
2. 行シフト処理の計算式 `i = r * 10 - 1 - k` を誤って `i = k`（正順）に変更するとどのような異常が発生するか、実際に試して観察してください
3. 「消去した行数（`lines`）」ではなく「設置したミノの数（`placed`）」に応じて落下速度が上がるように計算式を変更してみましょう

`soft % 3 == 0`（3 の倍数の tick）でのみ、落下処理手順 `fall` を呼び出します。「1 段落下し、底に着いていたら固定する」という処理は核の自然落下でもまったく同じものが使われるため、共通手順 `fall` として切り出すことでコードの重複を完全に排除しています。

### 8-2. `break` — 途中で抜ける

ハードドロップは「落ちられる限界まで一気に落下させ、その場で即座に固定する」操作です。何段落下できるかは盤面の状態によって事前に分からないため、無限ループ `loop while true` を回し、進めなくなった瞬間に **`break`** で脱出します。

<!-- figure: 08-controls Play/hardDrop -->
<!-- 生成物（scripts/generate_tutorial_figures.py）。手で編集しない -->
<img src="images/tutorial/08-controls-Play-hardDrop.svg" width="360" alt="手順 hardDrop の図">

| 番号 | 記号 | Do | 内容 |
|---|---|---|---|
| 1 | 小さな四角 | `let` | `ok = false` |
| 2 | 多角形（3 角） | `loop` | `true` の間、中を繰り返す |
| 2.1 | 円（内へ線 = 自陣の手順） | `cast` | `ok ← fits(piece.kind, piece.rot, piece.x, piece.y + 1)` |
| 2.2 | 弦（分岐） | `if` | `not ok` が真なら t の列へ |
| 2.2t1 | 外へ抜ける線（横棒） | `break` | いちばん近い繰り返しを抜ける |
| 2.3 | 四角 | `set` | `piece.y ← piece.y + 1` |
| 3 | 円（内へ線 = 自陣の手順） | `cast` | `lock()` |
<!-- /figure -->

- **`break`**: 最も内側の `loop` を直ちに中断してループ外へ脱出するステップです。図では環の外へ抜ける線（先端に横棒）です
- 盤面には必ず底（行 19 または蓄積ブロック）が存在するため、`fits` は有限回で必ず `false` を返し、安全にループを抜けます（万が一終了条件を満たさない無限ループを記述した場合でも、Jin のランタイムは 1 tick あたりの最大実行ステップ数上限で安全に強制停止します）

### 8-3. 次のミノの予告

次に落ちてくるミノの種類を変数 `next` に保持し、右側の情報パネル（`paintPanel`）に描画します。描画のインデックス計算式は `(next * 16 + i) * 2` です（第 4 段階の式において `rot = 0` とした簡略形です）。

また、道具環に `audio`（音響機能）を追加しました：

- `audio.tone(220, 30)`: 220 Hz の低音を 30 ミリ秒鳴らす（ブロック着地時）
- `audio.tone(660, 60)`: 660 Hz の高音を 60 ミリ秒鳴らす（行消去時）

手順 `control` のステップ数はこれで 9 個となりました。12 個の上限（JIN210）に近づいており、適切な関数分割が行われていることがわかります。

### 練習問題

1. ↓ キーを押した瞬間（`pressed`）にも即座に 1 段落下するように処理を追加してみてください。押下時と長押し時の両方のハンドリングが必要な理由を考察しましょう
2. 4 行同時消去（テトリス）を達成したときだけ、特別な高い音を鳴らすように条件分岐を追加してください
3. ハードドロップで一気に落下させた段数 × 2 点のボーナススコアが入るように改造してみましょう

## 9. 結果画面 — 陣の流れ

**ファイル**: [`docs/samples/tetris/09-tetris.jin`](samples/tetris/09-tetris.jin)（= [`examples-v2/tetris/tetris.jin`](../examples-v2/tetris/tetris.jin)）

ブロックが上まで積み上がると GAME OVER 画面に切り替わり、RETRY ボタンで最初からやり直し、QUIT ボタンでゲームを終了できます。これがテトリスの完成形です。

### 9-1. 陣を並べる — `flow`

これまでの段階では、すべての処理が `Play` という単一の陣の中に書かれていました。しかし、「ゲームプレイ画面」と「ゲームオーバー結果画面」のように**責務や画面遷移が異なる場面は、別の陣に分割する** のが優れた設計です。

複数の陣を管理する場合、トップレベルに手順を持たない**核なし陣（Root Circle）** を配置し、画面の流れ（ライフサイクル）を定義します。

<!-- figure: 09-tetris flow Game -->
<!-- 生成物（scripts/generate_tutorial_figures.py）。手で編集しない -->
<img src="images/tutorial/09-tetris.svg" width="360" alt="陣全体の図">

核なし陣 `Game` の `flow`

| 欄 | 値 |
|---|---|
| `kind` | `loop` |
| `steps` | `Play`, `Result` |
| `exit` | `Result.quit` |
<!-- /figure -->

ルート陣 `Game` は、「`Play` 陣が終了したら `Result` 陣を開始し、`Result` 陣が終了したら再び `Play` 陣を開始する」というループフローを定義しています。このループは `Result.quit` が真になるまで繰り返されます。`Play` 陣が `finish` すると、自動的に `Result` 画面へと遷移します。

### 9-2. 他の陣の値を読む

結果画面である `Result` 陣は、暗転したゲーム盤面を背景に敷いた上で「GAME OVER」の文字と最終スコアを描画します。盤面データや得点は `Play` 陣が保持している状態ですが、**`out: true` が指定された変数は、`陣名.変数名` という構文で他の陣から読み取り専用（Read-only）で参照できます**。

`Result` 陣の手順 `menu` では、`Play.board[i]` や `Play.score` を読み取って描画しています（他の陣の状態を直接書き換えることはできません。各陣の状態変更権は自分自身のみが持ちます）。これまで `board`, `score`, `lines` に `out: true` を指定していたのは、この画面間共有のためでした。

### 9-3. ボタン

道具環の `ui` を用いて、クリック可能な GUI ボタンを配置します。

境界環に **`guards`**（不変条件アサーション）を追加しました。

## 10. デバッグ — 動きを目で追う

プログラムは意図した通りではなく、記述された通りに動作します。不具合の原因を特定するための 3 つのデバッグ手法を紹介します。

### 10-1. トレース — 全部の記録

ターミナル実行時に `--debug` と `--trace` オプションを付与することで、すべての実行ログを JSON Lines（JSONL）形式でファイルに出力できます。

```bash
uv run jin run docs/samples/tetris/09-tetris.jin --ticks 60 --debug --trace /tmp/t.jsonl
head -3 /tmp/t.jsonl
```

```
{"seq":0,"tick":-1,"circle":"Play","kind":"enter","name":"Play","pointer":"/circles/1", … }
{"seq":1,"tick":-1,"circle":"Play","kind":"rite","name":"begin","pointer":"/circles/1/rites/0", … }
{"seq":2,"tick":-1,"circle":"Play","kind":"set","name":"score","pointer":"/circles/1/rites/0/steps/0", … "output":0}
```

1 行が 1 つの出来事（ステップの実行、変数の代入、関数の呼び出し）を克明に記録しています。`grep` コマンド等と組み合わせることで、「どの瞬間に変数の値が不正になったか」を特定できます。

### 10-2. 録画と再生

キーボード入力を記録した録画ファイル（`.jinrec`）を利用すれば、**過去のプレイ展開を何度でも 100% 同一に再現できます**。乱数のシード値が固定されているため、入力ログさえあれば完全に決定論的なリプレイが可能です。

```
{"jinrec": 1, "file": "tetris.jin", "seed": 3, "fps": 30, "ticks": 60}
{"tick": 2, "kind": "key", "name": "Space", "down": true}
{"tick": 3, "kind": "key", "name": "Space", "down": false}
```

エディタの実行パネルで **「録画」** を押してプレイし、**「録画を止めて書き出す」** をクリックすると、この `.jinrec` ファイルがダウンロードされます。CLI で入力として渡すことも可能です：

```bash
uv run jin run docs/samples/tetris/08-controls.jin --input space.jinrec
```

### 10-3. エディタでスクラブする

エディタの **「実行」モード** では、実行パネルで **「録画」** を押して操作し、**「録画を止めて書き出す」** で停止した後に「この録画を再生」をクリックすると、そのプレイの全トレースがエディタ内に読み込まれます。

下部に表示されるタイムラインスライダー（`upto`）をドラッグして動かすと：

- 魔法陣の上で、その瞬間に実行されていたステップがハイライト表示される
- 右側パネルに、その時点における記憶環の変数（`board` の中身、`score`、`piece` など）の正確な値が表示される
- ゲーム画面がその tick の描画状態にタイムトラベルする

「行が消えたはずなのに得点が増えない」「壁際で予期せぬ挙動をした」といった難解なバグも、問題が発生した瞬間にスライダーを巻き戻すことで、即座に原因を突き止められます。

## 11. 発展課題と用語対応表

### 発展課題

完成したテトリスをベースに、自分だけの新機能を追加してみましょう。

- **ゴースト表示**: ハードドロップした際の着地予想地点を半透明の枠で描画する（`hardDrop` の落下計算ロジックを別手順に切り出し、`paintBoard` から呼び出す）
- **ホールド機能**: Shift キーで現在のミノを一時キープし、後で入れ替えられるようにする（変数 `hold` の追加と `spawn` の分岐）
- **レベル表示**: 消去行数に応じたレベル `floor(lines / 5)` を情報パネルに表示する
- **ハイスコア保存**: ブラウザを閉じても記録が残る道具 `storage` を使って最高得点をローカル保存する（[`docs/spec/v2/abilities.md` §8](spec/v2/abilities.md) を参照）
- **本格的なウォールキック**: 回転時に壁やブロックと衝突した場合、左右や上下に数マスずらして回転可能か試行する（SRS: Super Rotation System の実装）
- **7-bag 乱数**: 7 種類のミノが偏りなく均等に出現するよう、7 個のミノを 1 セットとしてシャッフルして配分する
