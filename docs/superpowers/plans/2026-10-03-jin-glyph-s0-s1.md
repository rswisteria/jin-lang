# 陣書き S0(spike)+ S1(正典と語彙)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 手描きの式紋が Claude で読めるかを実測して紋を確定し(S0)、その語彙・欄の順・場面グラフ・JIN3xx を正典とコードで固定する(S1)。

**Architecture:** S0 は使い捨ての spike(`delivery/20260904-1445-jin/glyph-spike/`)で、升目シートの手描き → 撮影 → Claude 認識 → 正解との突き合わせを行い、結果を `glyph-recognition-probe.md` に残す。S1 は紋の語彙と欄の順を `jin_core.v2.glyph`(純データ。レンダラと読み取りの両方が import する)に、場面グラフを新パッケージ `jin_glyph.scene`(Pydantic)に置き、正典 `docs/spec/v2/glyph.md` の machine-readable 表と等号で固定する。

**Tech Stack:** Python 3.12+ / Pydantic(既存)/ pytest / spike だけ `anthropic` SDK と Pillow(`uv run --with` で一時的に使い、lock に入れない)

**Spec:** `docs/superpowers/specs/2026-10-03-jin-glyph-design.md`(以下 spec)

## Global Constraints

- テストはネットワークと API キーを要さない。Claude を叩くのは S0 の手動スクリプトだけ
- `jin_core` に画像ライブラリも `anthropic` も入れない(spec §0)。`jin_core.v2.glyph` は純データ
- サブコマンド 9 個・LSP の `jin/…` 6 種・v2 の `data-jin-kind` 13 種は変えない(S0 / S1 は描画も CLI も触らない)
- `schemas/*.json` は手で編集しない。`uv run python scripts/generate_schema.py` で生成する
- 認識のモデルは `claude-opus-5-5`、拒否への備えに `fallbacks: "default"`(spec §3.1)。**SDK の呼び方は記憶で書かない**: claude-api スキルの `python/claude-api/tool-use.md`(structured outputs)と `shared/model-migration.md`(fallbacks の `"default"` 形と beta ヘッダ `server-side-fallback-2026-07-01`)を読んでから書き、実測を probe に残す
- 写真を API に送るのは spike スクリプトを人が明示して走らせたときだけ。**走らせる前に費用の見積もりを人に示して承認を得る**
- S0 の合格線: 認識後の手直しが**升数の 2% 以内**(fib 80 升 → 2 升、clicker 463 升 → 9 升)で正解と一致(spec §9 #17)
- 紋の数: 式紋 36 字・判別の紋 21 字(spec §1.1)。判別の紋は決まった枠にだけ現れる
- コミットメッセージは日本語、末尾に `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`

## Review Focus

1. **写真が 90° / 180° 回っている** → 位置合わせが向きを取り違えず正しく読む(四隅の護符のうち 1 つを向きの印にする。Task 2 のシートと Task 4 の撮影で確かめる)
2. **升が空なのに何か読む(幻の字)** → 空の升は空と返り、幻の字は誤りとして数える(Task 3 の採点に入れる)
3. **日本語の文字列リテラル** → 中身がそのまま読める(clicker の文字列は ASCII だけなので、Task 2 で日本語の行を 1 行足す)
4. **紋とラテン文字の取り違え(紋 ↔ `o` / `l` / `x` など)** → 採点が取り違えの組を数えて報告する(Task 3)
5. **場面グラフの `t: "glyph"` に未知の紋 id** → Pydantic の検証で落ちる(Task 8 のテスト)
