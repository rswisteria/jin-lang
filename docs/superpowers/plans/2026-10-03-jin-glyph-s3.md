# 陣書き S3(決定的デコーダと構文解析器)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jin が描いた完全陣の PNG を読み戻し、元の `.jin` とバイト一致する正準形に戻す(Issue #113・設計書 §3.3 / §3.4 / §5)。

**Architecture:** 入れ子の境目を銘文に書く(構造の印 `s_else` / `s_end`・ユーザーの判断 B)ので、プログラムは**銘環の字の列だけ**から組み立てられる。
デコーダ(`jin_glyph.decode`)は完全陣の配置の規則(`jin_render.v2.full_layout`)を共有し、root の陣から順に銘環の位置を辿って升を読み、場面グラフを作る。
構文解析器(`jin_glyph.parse`)は場面グラフの銘帯を欄に割ってモデルを組み、`canonical.dumps` で正準形にする。升の読み取りは既知の字形
(線の紋は `glyph_paths`、ラテンはドットの字)との照合で、API を使わない。

**Tech Stack:** Python 3.12+ / Pillow(`jin-glyph` の実行時の依存・12.3)/ cairosvg(開発時だけ・2.9・往復テストで SVG → PNG)/ pytest

**Spec:** `docs/superpowers/specs/2026-10-03-jin-glyph-design.md`(§1.3 / §1.4 / §3.2〜§3.5 / §4.1 / §5 / §9)、正典 `docs/spec/v2/glyph.md`、Issue #113

## Global Constraints

- **往復の契約**: examples-v2 の 5 本と `tests/fixtures/v2-programs/*.jin` の全本で、`.jin` → 完全陣 SVG → PNG → デコード → 構文解析 → `canonical.dumps` が元の正準形とバイト一致
- テストはネットワークと API キーを要さない。PNG 化は cairosvg(`[dependency-groups].dev`)。`jin-glyph` の実行時の依存は `jin-core` / `jin-render` / Pillow だけ(`anthropic` は S4)
- `jin_glyph` を import するのは `jin_cli` だけ。`jin_render` の既定の出力は変えない(完全陣の出力は Task 1 の銘文の追加でだけ変わる)
- 診断の型は変えない。画像を入力にした診断は `.jinscene.json` に対して出す(diagnostics.md §5)。JIN301〜306 は fixture でちょうど 1 つずつ出す
- サブコマンドは 9 個のまま(画像は `check` / `fmt` だけが受ける・§9 #11)
- 依存の版は実測した値(cairosvg 2.9.1・Pillow 12.3.0・2026-10-03)を下限に置く
- コミットメッセージは日本語、末尾に `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`

## Review Focus

1. **root が `circles[0]` でないプログラム** → 往復で `circles[]` の並びが変わらない(Task 1 の root の欄・Task 6 のテストに fixture を足す)
2. **空の `then` と空でない `else`・空の `loop` 本文・入れ子 3 段** → `s_else` / `s_end` で境目が復元される(Task 1 / Task 5)
3. **PNG の倍率が違う(1 倍・2 倍・3 倍)** → 升の大きさを護符から逆算して同じ場面グラフになる(Task 4)
4. **k6x8 で同じ点の並びを持つ別の字** → どちらに読むかが決まっていて、fixture の文字列は往復する(Task 3)
5. **壊れた場面グラフ(始まりの印が無い・欄の数が違う・判別の紋が枠の外)** → 例外ではなく JIN3xx(Task 5)

### Task 4: デコーダ `jin_glyph.decode`(PNG → 場面グラフ)

**Files:**
- Create: `packages/jin-glyph/src/jin_glyph/decode.py`
- Test: `packages/jin-glyph/tests/test_decode.py`

**Interfaces:**
- Produces: `decode_png(data: bytes) -> JinScene`(`sheet = "free"` ではなく `"S"` / `"M"` でもないので、Literal に `"full"` を足す)

  手順:
  1. **升の大きさ**: 左上の護符(一辺 3 升・外枠は 0.2〜2.8 升・中の塗りは 0.9〜2.1 升)を対角線に沿って走査し、外枠の 2 辺の間隔 ÷ 2.6 を升の px とする。
     一辺の升数 = 画像の幅 ÷ 升の px、`half` = その半分
  2. **銘環を読む** `read_ring(center, inner)`: `ring_slot_center` で 1 周目の 12 時(始まりの印)から順に升を読み、周の最後が `cont` なら次の周へ、
     空の升・`cont` でない周の最後で終わる。読んだ升の列(始まりの印と `cont` を除く)と最外周の半径を返す
  3. **root**: 中心(0, 0)の銘環を陣の内縁(`circle_inner()`)で読む(先頭が `s_circle` でなければ JIN301 相当の失敗)
  4. **衛星**: 陣の中心から真上へ 0.25 升刻みで距離を走査し、`rite_inner()` の銘環の始まりの印 + `s_rite` が読めた距離を `D2` とする。
     陣の銘環より外で `s_circle` に当たれば衛星は無い。数 `n` は 12 から 1 へ、`orbit_centers` の全位置で `s_rite` が読める最大の `n`
  5. **第 1 軌道**: root の塊の外から真上へ同じ走査で `s_circle` の銘環を探し、`D1` と数 `m` を同じ方法で決め、各陣とその衛星を 3〜4 と同じく読む
  6. **額縁の銘帯**: `frame_positions` で読む(空の升で終わる)
  7. 場面グラフ: 図形は 額縁 `frame` / 陣 `c<軌道の順>` / 手順陣 `r<陣>_<衛星の順>`(`kind` は `frame` / `ring.circle` / `ring.rite`・`at` は画素の中心)、
     銘帯は図形ごとに 1 本(升の `box` は画素の矩形)

- [ ] **Step 1: 失敗するテスト**: fib / paddle / tetris の完全陣を cairosvg で 2 倍の PNG にして `decode_png` → 各銘帯の升の列(`t` / `v`)が `inscribe` の
  `frame_band` / `circle_ring` / `rite_ring` と**升ごとに等しい**。1 倍と 3 倍でも同じ場面グラフ(`box` を除く)になる
- [ ] **Step 2:** FAIL
- [ ] **Step 3:** 実装
- [ ] **Step 4:** PASS。tetris の所要時間を測り、30 秒を超えるなら原因を probe に残す
- [ ] **Step 5:** Commit(`feat(glyph): Jin が描いた完全陣の PNG を場面グラフに読む`)
