# Jin 鑑賞ページ(stage)— 魔法陣を作品として書き出す 設計

> 状態: ドラフト v0.1 / 2026-09-17
> 用途: Jin v2 の魔法陣を 3D・ライティング・発動の演出つきで見せ、動画 / 静止画として書き出す `apps/stage` の上位設計。
> §1〜§4 はブレインストーミングで節ごとに合意した内容である。§6 の決定事項表が合意の一覧で、実装はこの表から始める。
> 見た目の方向性はブラウザのモック 3 案(蒼星 / 金環 / 紅焔)を見比べて**金環**に決めた。

---

## 0. 目的・スコープ・非目標

### 目的

「プログラムがどう作られているか」への興味に対して、既存の表現(ソースコード・バイトコード・バイナリ)は視覚情報が乏しく、絵面で興味を持たせる力が弱い。Jin ではプログラム本体が魔法陣という絵を持つ。これを**美麗に、格好よく**見せ、プログラムを知らない人に絵で興味を持ってもらう。

世界観としては **魔法陣 = プログラム、詠唱 = 入力、魔法 = 出力** である。ファンタジーのフィクションで魔法を描くための言語として Jin が採用されることを期待しており、陣そのものと発動時の演出にビジュアルの質が要る。

### スコープ(第 1 段階)

- 対象は **Jin v2 だけ**(トレースと `.jinrec` があり、実行時の演出が意味を持つ)
- **外に見せる作品**を優先する: 鑑賞ページで `.jinrec`(詠唱)を再生し、陣が発動する様子を **MP4 / PNG** に書き出す
- 書き出しは**ブラウザの鑑賞ページ**から行う(CLI のヘッドレス書き出しは作らない)
- 構図は**魔法陣だけ**

### 第 2 段階(この設計の範囲外。構成は変えずに足せるようにしておく)

- 発動した魔法(ゲーム画面 = トレースの `frame` 行の表示リスト)を「召喚された像」として陣と合成する。音もここで扱う

### 非目標

- v1(ADK エージェント)の陣の 3D 化
- CLI / サーバ側での動画生成(10 個目のサブコマンドは作らない)
- GIF 書き出し、字幕やタイトルカードの編集機能
- **言語・実行系としての 3D**。v2 設計書 §0 の非目標「3D」は言語と `apps/player` の機能の話であり、この設計はそれを変えない。stage は**プログラムの見せ方**であって、`.jin` に 3D の語彙を足さず、プレイヤーにも 3D を入れない

### 継承する設計前提(変えない)

- **レンダラは Python 1 本。** 配置の唯一の元は `jin_render` が出す SVG である。stage は配置を計算し直さない
- **エディタは 1 本の線も描かない**(`test_the_editor_never_draws_the_magic_circle_itself`)。3D はエディタの外の別アプリで描く
- **レイアウト情報はファイルに保存しない**(要件書)。見せ方の設定は `.jin` に書かない
- `jin/…` は 6 種、サブコマンドは 9 個、プレイヤーとの語彙は 7 語のまま

## 1. 構成とデータの流れ

### 1.1 置き場所

`apps/stage` を**独立したアプリ**として作り、`jin editor` が `/play/` と同じ仕組みで `/stage/` として配る。エディタは stage を同一オリジンの iframe で開く。

```
jin editor ─┬─ apps/editor ── jin/renderSvg(LSP)→ SVG / jin/model → 名前の表
            │      │  ├─ /play/  (プレイヤー): jin.replay(.jinrec) → jin.trace(行)
            │      │  └─ /stage/ (鑑賞ページ・新規)
            │      └──── postMessage: SVG + 名前の表 + トレース行 + fps ──→ stage
            └─ 静的配信: apps/stage/dist を /stage/ に(探す順は --stage-dist > apps/stage/dist)
```

- **stage は Python にも LSP にも繋がない。** 受け取った SVG・名前の表・トレース行・fps から、3D の組み立て、演出、書き出しだけを行う
- **three.js と Mediabunny は stage にだけ入れる。** エディタとプレイヤーの bundle、`jin build --single` の出力は重くならない
- エディタ ↔ stage の語彙はプレイヤーの 7 語とは別の集合で、同じく等号で固定する(§4.2)。語の確定は実装時に行う(例: 親 → stage `stage.scene` / `stage.trace` / `stage.export`、stage → 親 `stage.status` / `stage.file`)
- `jin editor` に足すのは `--stage-dist` **オプション**だけで、サブコマンドは増えない

### 1.2 原則

1. **配置の元は SVG だけ。** stage は `data-jin` 要素の座標と種別を読み、層(z)・素材・演出を割り当てる。モデルから配置を計算しない。Phase 6 の記憶環の値ラベル(描かれた要素の矩形から位置を取る HTML 層)と同じ考え方を 3D に広げたもの
2. **演出の合図は pointer。** トレース行の `pointer` と SVG の `data-jin` の対応は、overlay の規則 1(`/` 区切りの段一致。エディタの `trace/filter.ts` と同じ)で取る
3. **時間軸は tick。** 絵は「tick + tick 内の割合」だけで決まる関数にする。§3 の 1 コマずつの書き出しがこれに依存する

### 1.3 退けた案

| 案 | 退けた理由 |
|---|---|
| エディタの中のモードとして組み込む | three.js がエディタに入り、「エディタは描かない」契約の趣旨とぶつかる |
| stage が自分で LSP に繋ぐ | 接続とトークンの防御が 2 本になる |
| SVG の中で飾る(`<filter>` / グラデーション) | 本物の 3D・ライティングが出せない。layout.md §2 の「2 色 + 強調 1 色」とも衝突する |
| 3D 側でレイアウトを再実装する | レンダラ 1 本の原則が崩れ、SVG と 3D の配置がずれる |

## 2. 金環の見た目と演出

### 2.1 立体の組み立て

陣ごとに 6 層に分け、上へ浮かせる。層は `<g data-jin="/circles/k">` の中で、**その陣の中心と外周からの相対**で決める(入れ子の小陣は SVG の中で縮小された `<g>` として入っている)。

<!-- machine-readable: stage-layers -->

| 層 | 中身(`data-jin-kind`) | 高さ(外周 1 に対して) |
|---|---|---|
| 0 台座 | `stage` / `form` | -0.32 |
| 1 境界環 | `circle`(半径 0.95 の輪)/ `on` / `guard` / `delegate` | 0 |
| 2 記憶環 | `circle`(0.75)/ `state` | +0.07 |
| 3 道具環 | `circle`(0.55)/ `sigil` / `flow-edge` | +0.14 |
| 4 手順環 | `circle`(0.35)/ `rite` | +0.21 |
| 5 核 | `core`(核・核の文字・紋章の点) | +0.28 |

<!-- /machine-readable -->

`step` / `step-edge`(手順の図)は第 1 段階では深さに応じて層 1〜4 に置く(深さ 0 → 層 1、深さ 3 → 層 4。v2 layout.md §3 の環の対応と同じ)。値はモックで決めた初期値で、実装で見え方を詰めて stage.md に確定値を残す。

- **素材**
  - `circle` の輪は金属のトーラス(metalness 1、roughness 約 0.3)。映り込み用に環境マップ(`RoomEnvironment` を PMREM で)を置く
  - 線(放射線・弦・四角・刻印)は細い金の線(`LineSegments2`)で、発光はごく弱い
  - 紋章の点は金の鋲(小さな球)。文字は第 1 段階では SVG の文字をテクスチャにする(ルーン文字のグリフフォントは別件。layout.md §2 の「グリフフォントは v2」)
- **光**: 暖色の主光源が陣の周りをゆっくり回り、逆光と弱い環境光を足す。トーンマッピングは ACES。ブルームはしきい値を高くし、**普段はほぼ光らせず、発動の瞬間だけ**滲ませる
- **背景**: 暗い空間、薄い霧、昇る火の粉
- **意味を持たない飾り**: 輪の外側の目盛りと、そのゆっくりした逆回転。輪の半径だけから作り、配置の情報を増やさない

### 2.2 名前の表

`cast` の `name` は `canvas.rect` のような能力名、`set` の `name` は state 名であり、SVG だけではどの紋・どの四角かが分からない。エディタは `jin/model` から次の表を作り、`stage.scene` に添える。

- 陣ごとの **sigil 名 → pointer**(`host` の名前空間名を含む)
- 陣ごとの **state 名 → pointer**

これは配置ではなく名前の対応である。解決できない名前は光らせない(例外を投げない)。

### 2.3 トレースの 13 種と演出

<!-- machine-readable: stage-effects -->

| kind | 演出 |
|---|---|
| `enter` | 起動。核から外周へ光が駆け上がり、層が一段ずつ浮き上がる |
| `exit` | 外周から核へ光が引き、層が沈む |
| `event` | `on` の ◇ が灯り、境界環の外から光の粒が吸い込まれる(詠唱が届く) |
| `rite` | 手順の小陣が点灯して一回転する |
| `cast` | 手順の小陣から、名前空間の紋へ金の光線。紋が共鳴する |
| `set` | 記憶の四角が明滅し、刻印の光が走る |
| `emit` | 境界環の外へ光の粒が放たれる |
| `transfer` | 委譲の小円へ太い光が流れ込む |
| `wait` | 手順の小陣の光が呼吸するように弱まる(`resume` で戻る) |
| `finish` | 陣全体が一度強く輝き、火の粉が噴き上がって静まる |
| `assert` | `guard` の △ が赤く明滅する(金以外で唯一の色) |
| `error` | 輪に亀裂の光が走り、陣が暗転する |
| `frame` | 光らせない。tick の終わりの刻みとして使う(第 2 段階で画面の合成に使う) |

<!-- /machine-readable -->

集合は runtime.md §5 の `trace-kinds` と等号(§4.2)。

### 2.4 光りっぱなしを防ぐ規則(慣れ)

paddle は 1 tick に約 10 行(`event tick` → `rite step` → `set ball` ×2 → `rite paint` → `cast canvas.*` ×5)を出し、毎 tick 同じ要素が発火する。すべてを同じ強さで光らせると常に光ったままになり、発動の瞬間が埋もれる。

- 要素ごとに「最近どれだけ発火したか」を持つ。**毎 tick 繰り返す発火は、低く一定の脈動(うなり)に落とす**
- 久しぶりの発火と、一度きりの kind(`enter` / `exit` / `emit` / `transfer` / `finish` / `assert` / `error`)だけを大きな演出にする
- `set` は**値が変わったときだけ**強く光らせる(`score` が上がる瞬間は光り、`ball` の毎 tick の更新はうなりに留まる)
- この状態は **tick 順にトレースを畳み込んで得る決まった値**である。演出の乱数(火の粉の散り方など)は `seq` から作る種で決める。「トレース + tick + 割合 → 場面」が一意に決まる

### 2.5 カメラ

- 構図の既定値は 3 つ: **俯瞰** / **斜め 45°**(モックの角度)/ **低い煽り**
- それぞれに、時間だけで決まるゆっくりした周回を付ける
- 手で動かせる。書き出しでは、その構図を初期値とする決まった動きにする

## 3. 書き出し

### 3.1 動画: 1 コマずつ描いて固める

- 描画ループを止め、`n` 枚目を「時刻 `n / 動画fps` → tick + 割合」で描いてから、Mediabunny の `CanvasSource.add(n / fps, 1 / fps)` に渡す(WebCodecs)。**実時間の録画(MediaRecorder)はしない**
  - その PC の速さに関係なく、4K / 60 fps でもコマ落ちしない(遅い PC では書き出しに時間がかかるだけ)
  - 同じ詠唱と同じ設定なら**同じ場面の列**になる。GPU やブラウザが違うとピクセル単位までは一致しないので、保証は「場面の列」までとし、stage.md にそう書く
- 形式は **MP4(H.264)が既定**。`canEncodeVideo` で先に確かめ、できなければ WebM(VP9)、どちらもできなければ書き出しを理由付きで無効にする(鑑賞はできる)。どれになるかを画面に出す
- 速度は 1× / 0.5×(tick と動画時刻の対応を変えるだけ)
- 音は入れない(第 2 段階)

### 3.2 静止画

指定した瞬間(tick + 割合)を、画面とは別に書き出し用の解像度で描き直して PNG にする。長辺は最大 4096 px。ブルームの滲みの幅は解像度に比例させ、プレビューと書き出しで見え方を変えない。

### 3.3 書き出しの設定

| 項目 | 選択肢(既定を太字) |
|---|---|
| 縦横比 | **1:1** / 16:9 / 9:16。比に合わせて陣が収まるカメラの距離を決める |
| 解像度 | **1080** / 1440 / 2160 |
| 範囲 | 再生バーで開始と終了の tick を選ぶ(**全体**)。上限は 60 秒相当 |
| 構図 | §2.5 の 3 構図(**斜め 45°**) |
| 速度 | **1×** / 0.5× |
| 銘 | 右下に小さく「陣名 — written in Jin(陣)」(**on**) |

- ファイル名は `<jin 名>-<陣名>-seed<seed>-t<開始>-<終了>.mp4` / `.png`(既存の `<jin 名>-seed<seed>-<ticks>t.jinrec` に揃える)
- 保存は、今の `.jinrec` と同じく**親(エディタ)がダウンロードさせる**。stage はバイト列を親に渡すだけ(ダウンロードの口を 1 か所に揃え、契約テストで固定しやすくする)
- 書き出し中は進捗(何枚目 / 全体)を出し、中止できる。中止したら何も渡さない

## 4. テストと契約

WebGL の絵をピクセル比較するとぶれるので、**絵の手前の純関数で決定性を固定する**。

### 4.1 単体テスト(`apps/stage/test/`・vitest)

| 対象 | 固定すること |
|---|---|
| SVG → 場面の記述 | 座標は SVG から来たものだけ。架空の座標の SVG を食わせると、その座標がそのまま出る。入れ子の `<g>` の中で層が相対的に決まる |
| 種別 → 層の表 | `data-jin-kind` の 13 種(`jin_render.DATA_JIN_KINDS_V2`)と等号 |
| トレースの畳み込み | 演出表が runtime.md §5 の `trace-kinds` と等号。繰り返しはうなりに落ちる。`set` は値が変わったときだけ強い。同じ入力と時刻なら同じ状態。乱数の種は `seq` から |
| 名前の表 | `cast canvas.rect` → `canvas` の紋、`set score` → `score` の四角。解決できなければ光らせない |
| 時間の対応 | `n` 枚目 → `n / fps` → tick + 割合。範囲と速度 |
| カメラ | 3 構図 × 縦横比 3 種で陣が画面に収まる |
| 書き出しの細部 | ファイル名の形。中止で何も渡さない。コーデックの選択(H.264 → VP9 → 不可) |

### 4.2 契約テスト(`tests/contract/test_stage_contract.py`)

- `apps/stage` の実行時依存は **three と mediabunny だけ**で、probe した版に完全一致。ツールチェーンはエディタと同じ版
- `apps/editor` と `apps/player` の `package.json` に three / mediabunny が**無い**
- stage は Python パッケージを import せず、リポジトリのファイルを読まない(eslint の `no-restricted-imports` + `test/dependencyDirection.test.ts`)
- エディタ ↔ stage の語彙を、両側の 2 ファイルから抜いた集合の**等号**で固定する。プレイヤーの 7 語は変わらず、互いの語彙が相手のファイルに現れない
- stage.md の `stage-layers` / `stage-effects` の表と実装の表が一致する
- 既存の契約(エディタは描かない / `jin/…` 6 種 / サブコマンド 9 個)は変更なしで緑
- CI に stage のゲート(build / lint / test / e2e)のジョブがあり、editor ジョブが e2e の前に stage をビルドする

### 4.3 `jin editor` の配信(`packages/jin-cli/tests/test_editor.py`)

- `/stage/` を `/play/` と同じ規則で配る(`--stage-dist` > `apps/stage/dist`)
- `/stage/../` で抜けられない(`translate_path` の正規化を通す)。dist が無ければ 404 で、エディタが 1 行出す

### 4.4 e2e(`apps/stage/e2e/`・Playwright の Chromium)

- `jin editor examples-v2/paddle/paddle.jin` を起動して stage を開き、`tests/fixtures/jinrec/paddle-120.jinrec` を再生する。stage が受け取ったトレースが `jin run --input` の行と一致する
- 360p・1 秒で書き出す。PNG が出る。動画は選ばれたコーデックでファイルになり、Mediabunny で読み戻すとコマ数と長さが合う

### 4.5 先に実測すること(probe)

API は記憶で書かない。実装の最初に `delivery/<ラン>/stage-api-probe.md` に実測を残す。

- three 0.186.0: `LineSegments2` / `LineMaterial` / `UnrealBloomPass` / `OutputPass` / `RoomEnvironment` の import パスと引数(モックで一部確認済み。`THREE.Clock` は非推奨で `THREE.Timer` を使う)
- Mediabunny 1.57.0: `Output` / `Mp4OutputFormat` / `BufferTarget` / `CanvasSource.add(時刻, 長さ)` / `canEncodeVideo`(`mp4-muxer` / `webm-muxer` は非推奨で Mediabunny に置き換わっている)
- **Playwright の Chromium で H.264 のエンコードができるか。** できなければ e2e は VP9 の分岐を固定し、H.264 は手元の Chrome で人手確認する
- CI(GPU なし・SwiftShader)で WebGL とブルームが動き、1 秒の書き出しが現実的な時間で終わるか

### 4.6 変異の実測

`delivery/<ラン>/stage-mutations/mutate_stage.py` を置き、防御を壊すと赤くなることを隔離コピーの上で実測する。

- 座標を stage 側で計算する
- 語彙を 1 語増やす
- 繰り返しの抑制を外す
- `/stage/` の正規化を外す

### 4.7 文書

- 正典 `docs/spec/v2/stage.md` を新設する(層の表・演出の表・慣れの規則・時間の対応・書き出し・語彙)
- CLAUDE.md の進み具合の表と要点の節

## 6. 決定事項表

| # | 決めたこと | 選んだ案 | 主な理由 |
|---|---|---|---|
| 1 | 何を優先するか | 外に見せる作品(動画 / 静止画) | プログラムを知らない人に届けるには、共有できる絵が最も効く |
| 2 | 書き出しの場所 | ブラウザの鑑賞ページ | CLI の契約を変えずに絵の質へ集中できる。1 コマずつの描画なので後から CLI を足しても作りは変わらない |
