# Jin 陣書き(glyph)— 1 枚の絵がプログラムになる 設計

> 上位設計は `docs/superpowers/specs/2026-09-13-jin-v2-general-design.md`(以下「v2 設計書」)。
> v2 のモデル・実行系・ホスト境界はすべて引き継ぎ、**画像を `.jin` と並ぶ 2 つ目の直列化**として足す。
> 2026-10-02 のプレゼンで見えた世界観(紙や画像の魔法陣をそのままプログラムとして読む)を実現する。
> 決定は §9 の表に番号付きで残す(対話で人間が選んだもの)。

## 0. 目的・スコープ・非目標

### 目的

1. 紙に書いた魔法陣や PNG 画像を取り込み、プログラムとして解釈して実行できるようにする
2. 関数(手順)などの階層を入れ子の縮小図や別図に逃がさず、**1 枚の絵**でプログラム全体を表す
3. 名前・式・リテラルも絵に載せ、**画像にプログラムの情報がすべて含まれる**ようにする

3 つは 1 つの契約に畳める: **`.jin`(正準形)→ 画像 → 読み取り → `.jin` がバイト一致する**(§5.1)。

### 成功条件

- examples-v2 の 5 本と `tests/fixtures/v2-programs/` の全本が、Jin の描いた完全陣(PNG)から往復でバイト一致する
- 印刷した型紙に手で描いた fib / clicker を撮影して取り込むと `jin check` を通り、実行パネルで動く
- 白紙にフリーハンドで描いた fib が同じ経路で動く(段階 S6)

### スコープ

- 視覚文法: 構造紋・式紋・ラテン層、銘帯と欄の順、始まりの印(§1)
- 完全陣のレイアウト(連環陣)、銘環、型紙、1 枚の容量(§2)
- 読み取り: 場面グラフ、Claude 認識器、決定的デコーダ、構文解析器、診断(§3)
- CLI / エディタの入口、新パッケージ `jin-glyph`(§4)

### 非目標

- 実行時の意味論・JIL・ホスト境界・プレイヤーの変更(画像は `.jin` の前段で済ませる)
- asset(絵と音)の**中身**と、`agent.file` が指す v1 の陣の中身を画像に入れること(パスだけ載せる・§9 #3)
- 取り込んだ画像を正本として編集し続けること(取り込んだ後の正本は `.jin`・§9 #12)
- ローカルの手書き分類器(認識器は Claude の視覚モデル・§9 #5)

### 継承する前提(変えない)

- **意味モデルの唯一の真実は `jin_core.v2.model` の Pydantic 定義**。`.jin`(JSON)は正本のまま
- 正準形は `jin_core.canonical` の 1 か所。式の構文解析は `jin_core.v2.expr` の 1 か所(式の構文解析器を新しく作らない)
- サブコマンドは 9 個、LSP の `jin/…` は 6 種(どちらも増やさない・§4)
- 描画は決定的(同じ `.jin` から同じ SVG)。座標は `fmt_coord` 1 本・3 桁固定小数・楕円弧 `A` 不使用・`<style>` 不使用
- テストはネットワークと API キーを要さない
- `jin_core` は最下層で、画像ライブラリも `anthropic` も入れない

## 1. 視覚文法

### 1.1 三層の語彙

| 層 | 担うもの | 字形 |
|---|---|---|
| 構造紋 | 陣・環(記憶 / 道具 / 手順 / 境界)・ステップ 11 種・委譲・flow | v2 layout.md §2 / §3 の図形をそのまま使う |
| 式紋(新設・36 字) | 演算子 15(`+ - * / % ++ == != < <= > >= and or not`)、括弧 6(`( ) [ ] { }`)、`,` `:` とメンバの `.` の 3、文字列の括りの開閉 2、エスケープ 1、`true` / `false` の 2、型 5(`num` `bool` `str` `list<` の開閉)、欄の区切り 1、銘環の継ぎ 1 | 円・弧・点・短い線の組み合わせで新たに設計する。銘帯のどこにでも現れる |
| 判別の紋(新設・22 字) | `loop` の種別 3(each / while / count)、`wait` の種別 2(ticks / until)、sigil の種別 3(host / summon / agent)、asset の種別 2(sprite / sound)、flow の種別 3(sequence / parallel / loop)、`on` の event 5(tick / key / pointer / message / exit)、省略できる欄の印 4(`cast` の `into`・`loop count` の `name`・`guard` の `message`・state の `out`。`out` は S2 の後に足した 22 字目・§9 #28) | **決まった枠(銘帯の先頭か、その欄の直前)にだけ**現れる。認識器は枠ごとに 2〜5 個の候補から選べばよい |
| 構造の印(新設・23 字・S2 で 21 字・S3 で 2 字) | 銘環の中で**銘文 1 本の頭**に置き、どの図形の銘文かを示す(区切りを兼ねる): ステップ 11 種・陣の核・手順陣の核・記憶・道具・`on`・`guard`・委譲・型紙・asset・`description`、入れ子の境目 2 字(S3: `else` の始まり `s_else`・`if` / `loop` のブロックの終わり `s_end`・§9 #29) | 構造紋を升 1 つに縮めた形(§1.3・§9 #24) |
| ラテン層 | 名前(陣・手順・state・引数・型紙・欄・sigil)、数値リテラル(小数点・指数を含む)、文字列の中身(日本語を含む任意の文字) | 普通の文字 |

ラテン層と式紋の折衷にした理由は §9 #6。

**式紋の設計規則**

- ラテン文字・数字に似せない(O / 0 / l / 1 / I / x / v / s / c / o / e と紛れる形を使わない)。認識器が名前と紋を取り違えないため
- 対になるもの(開き括弧と閉じ括弧、`<` と `>`、`<=` と `>=`)は鏡像
- 1 字 3 画以内。升目 1 つに収まる
- 字形の確定は段階 S0 の spike(手描き → Claude で字ごとの正解率を測る)の後。表は正典 `docs/spec/v2/glyph.md` に SVG で置く

### 1.2 銘文

- 式は `expr` 文法と**同じ並び(中置)**でトークンを 1 つずつ書く。`a + b` は「`a`・加算の紋・`b`」
- 読み取りは「銘文 → トークン列 → 式紋を ASCII に写す → `jin_core.v2.expr.parse_expr`」。往復の一致は `canonical.dumps` の正準化(expr.md §8)が保証する
- 文字列は括りの紋で挟み、中身は文字のまま書く。描けない文字(制御文字・`"`・`\`・**空白**)はエスケープの紋 + ラテン文字(`n` / `t` / `s` / `u` + 16 進 4 桁 …)で書く。集合は expr.md §1 の JSON エスケープに空白(`s`)を足したもの(空白の升は空の升と見分けられない。視覚層だけの規則・`jin_core.v2.glyph.ESCAPE_LETTERS`)
- 数値は `str(x)` の書式(runtime.md §6)で書く。正準形が数値の字面を一意に決めるので往復が崩れない

### 1.3 銘文の置き場(銘環)と欄の順

図形の銘文は図形の脇には書かず、**陣・手順陣の外周を巡る同心の文字の環(銘環・§2.3)にまとめて書く**(§9 #24。
本物の魔法陣が円の周りに文字を何重にも巡らせるのと同じ形)。図形 1 つの銘文(以下「銘帯」)は、その図形の**構造の印**
(§1.1)で始まり、次の構造の印か銘環の終わりまで続く。欄は種類ごとに決まった順で、欄の区切りの紋で区切って書く。
省略できる欄は、その欄に固有の紋の有無で見分ける(例: `let` の `type` は型紋で始まる欄があるときだけ)。

どの銘環に何が載るか:

- **陣の銘環**: 陣の核 → `description` → 記憶 → 道具 → `on` → `guard` → 委譲(それぞれモデルの配列順)
- **手順陣の銘環**: 手順陣の核 → ステップを**前順**で。`if` は then →(`else` が空でなければ `s_else` → else)→ `s_end`、`loop` は本文 → `s_end`(本文が空でも書く)。入れ子の境目は銘文だけで決まる(S3・§9 #29)
- **額縁の銘帯**: 額縁の 4 辺を左上から時計回りに巡り、額縁の欄 → 型紙 → asset

図との対応: 図の中のステップの並び(12 時から時計回り・入れ子は親の弧の中)と銘環の構造の印の並びを**先頭から順に**対応させる。
種類が食い違えば JIN302。

| 図形 | 銘帯の欄(順) |
|---|---|
| 額縁 | 正典の印(`$schema`。標準の URL `https://xtone.internal/jin/schemas/jin-v2.schema.json` なら印だけ、他の値なら全文を銘帯に書き、無ければ印も無い)・`width`・`height`・`fps`・`seed`(既定値の欄も書く。正準形で既定値を落とすのは構文解析器の後段) |
| 型紙の印章 | 名前、欄ごとに「名前 `colon` 型」(`comma` 区切り) |
| 陣の核 | 名前・`core` の手順名(核なし陣は flow の kind の紋・`exit`) |
| 記憶の四角 | 名前・型・`init`・(`out: true` なら判別の紋 `mark_out`。図の二重線は画素からは読めない大きさ・§9 #28) |
| 道具の紋 | 名前・種別の紋・`host` / `circle` と `rite` / `file` |
| asset の印 | 名前・種別の紋・`path` |
| 手順陣の核 | 名前・引数「名前 `colon` 型」の並び・`returns` |
| `set` | `target`・`expr` |
| `let` | `name`・(`type`)・`expr` |
| `cast` | `target`・`args` の並び・(`into`) |
| `if` | `cond` |
| `loop` | `each`: `name`・`in` / `while`: `cond` / `count`: `times`・(`name`) |
| `wait` | `ticks` または `until`(どちらかを紋で示す) |
| `emit` | `circle`・`message`・`args` の並び |
| `return` | (`expr`) |
| `transfer` | `circle` |
| `on` の刻印 | event の紋・`rite` |
| `guard` の刻印 | `assert`・(`message`) |
| `delegate` の小円 | 委譲先の陣名 |
| `description`(陣だけが持つ) | 文字列 1 本(陣の銘環の核の次・§9 #3) |

`break` / `finish` は欄を持たない。`return` の `expr` は唯一の欄なので、銘帯が空かどうかで有無が決まる(印は要らない)。
文字列の欄(`description` / `message` / `path` / `file` / `host`)は式ではないが、銘文の書き方は文字列リテラルと同じ(括りの紋で挟む)。

### 1.4 順序

- 各環の **12 時に「始まりの印」**を置き、要素の配列順はそこから**時計回り**に数える(v2 layout.md の角度の規約と同じ)
- 入れ子のブロック(`then` / `else` / `loop.steps`)は親の弧の中で時計回り(layout.md §3 と同じ)
- 陣の並び(`circles[]`)・手順の並び(`rites[]`)は第 1 / 第 2 軌道の始まりの印から時計回り(§2.2)
- 型紙(モード 2)には始まりの印と 12 の目盛りを刷る。フリーハンド(モード 1)では描き手が始まりの印を描く(視覚文法の必須要素)

## 2. 完全陣のレイアウト(連環陣)

### 2.1 不変条件: 升の大きさは 1 枚の中で一定

今の陣の図は入れ子を 0.28 倍に縮め、深さ 1 から先を点にする(layout.md §1)。完全陣は逆に**升(1 字の大きさ)を全体で一定**にする。
陣と手順陣の**図の大きさは升で数えた固定値**(紋が升と同じくらいの大きさで読めるように)で、銘文の量は図の大きさを変えず、
外周の銘環の**周回数**だけを変える(§2.3)。人にとってはどの手順も同じ密度で読め、認識器にとっては升の大きさが 1 つに決まる。
入れ子の陣(summon / flow の参照)は縮めて描かず、点と線で参照だけを示す(本体は第 1 軌道に同じ大きさで描かれる)。

### 2.2 二段の軌道

- **第 1 軌道(陣)**: root を中央に置き、残りの陣を `circles[]` の順に 12 時から時計回りに並べる。flow の弦・多角形・`exit` の印は今の規則で陣同士を結ぶ
- **第 2 軌道(手順)**: 各陣の周りに、その陣の手順を**同じ升の大きさの衛星の手順陣**として並べる。中身は今の手順の図(深さ 0〜3 の環・弦・分岐の線)と、外周の銘環
- 陣本体の 4 環は残す。手順環の小さな印から対応する衛星へ線(へその緒)を引く
- 円どうしの線(S2 で確定・正典 glyph.md §8): 陣と手順陣のへその緒・`summon` の道具 → 呼ぶ手順陣(破線)・flow の弦・委譲(破線)の 4 種。線は互いの最外周の外で結び、交差を許す。自陣の手順への `cast`・`emit`・`transfer` の線は描かない(参照の正本は銘文)
- 額縁の銘帯は額縁の 4 辺を左上から時計回りに巡る(額縁の欄 → 型紙 → asset・§1.3)
- 配置は決定的。座標の規律は継承する(§0)。具体値(軌道の半径・衛星の間隔)は段階 S2 の実装で決め、`glyph.md` に根拠付きで残す(v2 layout.md §8 と同じ運び)
- **キャンバスは中身に応じて広がる**。完全陣では升を正規化単位で固定し、viewBox を配置の外接矩形 + 額縁から決める(既存の「正方形キャンバス 1000 px・R = 1」は既存の描画にだけ効く)。額縁は正方形のまま、一辺が広がる
- **完全陣は `<text>` を使わない**。銘文・名前はすべて清書体のパスで描き、既存の図の頭文字と核の手順名は描かない(名前は銘環に全文がある)(フォントの違いで決定的デコーダとラスタライズが環境ごとに割れないため)
- 四隅の護符は**一辺 3 升の固定寸法**で描く。読み取り側は護符の画素の大きさから升の画素数を逆算する(完全陣と型紙で共通)

### 2.3 銘環

陣・手順陣の銘文はすべて、図の外周に置く同心の**銘環**に書く(§1.3・§9 #24)。

- 1 周目は図の外接円の外側に置き、12 時の**始まりの印**から時計回りに升を並べる。周の升が尽きたら、その周の最後の升を
  **継ぎの紋**(`cont`)にして、1 つ外側の周の 12 時から続ける。周回数は字数から決定的に決まる(tetris の 449 トークンの表も周を増やすだけ)
- 1 周に入る升の数は周の長さ ÷ 升で決まる(外側の周ほど多い)。周の間隔・升の大きさは S2 で決めて `glyph.md` に残す
- 銘帯の頭には構造の印を置き、銘帯は周をまたいでよい(継ぎの紋が切れ目を示す)

### 2.4 容量(S2 で実測)

**S2 の実測(2026-10-03・正典 glyph.md §8)**: A3 に刷ったときの 1 升は fib 2.43 mm / clicker 2.04 mm / paddle 0.91 mm /
tetris 0.52 mm / othello 0.46 mm。すべて 1 枚に収まるが、下の見積もり(手描き 5 mm・印刷 2 mm)には届かない。主因は配置の詰め方
(第 1 軌道の距離が最大の塊で決まり額縁の中が空く)で、改善は S2 の後の課題。tetris / othello は当面「Jin が描いた PNG を読む」に限る。
手描き(モード 2)の型紙は S4 で升 5 mm を前提に別に組む(§2.5)。以下は S2 前の見積もり(経緯として残す)。

銘文の升数(名前・式・区切りを 1 字 1 升で数えた値。2026-10-02 に examples-v2 で計測):
fib 80 / clicker 463 / paddle 943 / tetris 3630 / othello 4871。

正方形 A3(約 280 mm 角)で紙の 3 割に銘文が載るとした見積もり:

| 書き方 | 1 升 | A3 1 枚の目安 | 収まる例 |
|---|---|---|---|
| 手描き(モード 2 / 1) | 5 mm | 約 900 升 | fib・clicker(paddle は境界) |
| Jin が描いて印刷 → 撮影 | 2 mm | 約 5900 升 | tetris・othello まで |
| PNG のまま読む | 画素で決まる | 実質的に上限なし | すべて |

手で描く対象は fib〜clicker 規模、それより大きなものは「Jin が描いた陣を読む」使い方とする(§9 #8)。額縁は正方形を保つ(§9 #9)。

### 2.5 型紙(モード 2)

- 型紙は**容量の等級ごとの骨格プログラムを、完全陣と同じレイアウト規則で描いたもの**。等級は S(1 陣 × 4 手順)と M(3 陣 × 各 4 手順)の 2 つから始める(§9 #10)
- 刷るもの: 四隅の位置合わせの印(四方の護符の意匠)・等級の印・各環の始まりの印と 12 の目盛り・銘帯の升目・余白の「続きの銘環」(番号の紋で飛ぶ)
- 認識器は等級から幾何を知る。幾何は `jin_render.v2.geometry` を共有し、レイアウトを二重に実装しない
- `jin render --sheet S|M` で出す。**S2 では作らず S4(Claude 認識器)で作る**: 型紙の升目の数と配置は認識器の切り出しと一緒に決めるため(§9 #27)
- **S4 で確定(正典 glyph.md §10.1)**: 銘環・額縁の銘帯・護符の規則は完全陣と共有し、大きさだけを型紙の定数(1 升 5 mm・一辺 285 mm)で決める(§9 #35)。S は陣を中央・手順陣を斜め 4 方向(右上から時計回り)、M は 15 の環を 4 × 4 の格子。「続きの銘環」は余白の横一列の**続きの帯**にし、番号を書かせず継ぎの紋 → まだ使っていない帯を番号の順に続ける(§9 #36)。`jin render x.jin --sheet S` は写し書きの手本(§9 #40)

## 3. 読み取り

### 3.1 流れ(モード 2)

```
写真 ─①位置合わせ─▶ 正面化 ─②切り出し─▶ 断片 ─③認識─▶ 場面グラフ ─④構文解析─▶ モデル ─⑤ canonical.dumps / jin check
```

| 段 | 内容 | 使うもの |
|---|---|---|
| ① 位置合わせ | 写真全体(S4 では長辺 1568 px に縮小)を 1 回渡し、四隅の護符と等級の印の座標だけを返させる。座標は幅・高さに対する比で受け、護符の塗りの重心で詰め直す(§9 #38) | Claude + Pillow |
| ② 正面化・切り出し | 射影変換で型紙の座標系へ戻し、等級の幾何から銘帯と紋の欄を切り出す | Pillow(OpenCV は入れない) |
| ③ 記号の認識 | 断片を 1 要求に複数並べ、欄ごとに「ラテンか紋 id か・読み・迷い(候補)」を返させる。紋の字形表は画像で最初の user の先頭に置きキャッシュする(`system` は text しか受けない・§9 #39) | `claude-opus-5-5`・`client.beta.messages.parse()`(構造化出力)・`fallbacks: "default"` |
| ④ 構文解析 | 場面グラフ → モデル(§3.3) | `jin-glyph`。決定的 |
| ⑤ 検査 | 正準形にして既存の検査 | 既存 |

**Claude に `.jin` を書かせない。** Claude が返すのは欄ごとの記号だけで、プログラムは ④ が組む
(LLM に JSON を転記させると二重エスケープなどで崩れることを v1 で実測している)。

### 3.2 場面グラフ(`.jinscene.json`)

認識器と構文解析器の間の唯一の契約。版付きの JSON で、schema は Pydantic から生成して `schemas/jin-scene.schema.json` に置く。

```jsonc
{ "jinscene": 1, "sheet": "S",                 // 等級。モード 1 は "free"
  "image": { "sha256": "…", "width": 4032, "height": 3024 },
  "figures": [ { "id": "f12", "kind": "step.set", "at": [x, y], "ring": "f3", "angle": 41.5 } ],
  "bands":   [ { "owner": "f12", "cells": [ { "t": "latin", "v": "s", "box": [x0, y0, x1, y1] },   // 1 升 = 1 字(score は 5 升)
                                            { "t": "latin", "v": "c" }, …,
                                            { "t": "glyph", "v": "sep" },
                                            { "t": "glyph", "v": "add" },
                                            { "t": "latin", "v": "1", "unsure": ["l", "I"] } ] } ],
  "lines":   [ { "from": "f12", "to": "f30", "style": "dashed" } ] }
```

- 写真の隣に `<写真名>.jinscene.json` として保存する。`image.sha256` が一致すれば API を呼ばずにこれを使う(2 回目以降は決定的・無料)
- 人が手で直してよい。テストの fixture もこの形式で書く
- `--offline` は隣のファイルだけを読み、無ければ失敗する(送信しない)

### 3.3 構文解析器(場面グラフ → モデル)

1. 組み立て: 包含(どの環の上か)と始まりの印からの角度で、陣・環・ステップの木と配列順を決める
2. 欄の割り当て: 図形の種類ごとの欄の順(§1.3)に、欄の区切りの紋で銘帯を切る
3. 式の写し: 式紋を ASCII のトークンに写し、`jin_core.v2.expr.parse_expr` へ
4. 迷いの解消: `unsure` の候補を欄の文法で絞る(数の欄は数字、名前の欄は既出の名前を優先)。決まらなければ第一候補を採り警告
5. 対応表: JSON Pointer → 画像上の領域(`box`)を一緒に出す。⑤ の診断を写真の座標へ戻すのに使う

### 3.4 決定的デコーダ(Jin が描いた PNG)

完全陣の銘文は**固定の清書体**(ラテン文字と式紋の線の字形)で描く。升の大きさが一定(§2.1)なので、読み取りは
既知の字形との照合で足りる(API を使わない)。出力は同じ場面グラフで、④ 以降は共通。往復の契約テスト(§5.1)はこの経路で取る。

### 3.5 診断(3 段)

| 段 | 例 | 出し方 |
|---|---|---|
| 認識の迷い | `1` か `l` か | 警告。写真の上で升を囲む |
| 絵の文法の誤り | 始まりの印が無い・欄の数が合わない・継ぎの紋の先が無い | **新しい番号帯 JIN3xx**(「絵の文法」)。位置は画像の座標 |
| 意味の誤り | 未定義の名前・型の不一致 | 既存の JIN2xx。§3.3 の対応表で画像の座標へ戻す |

**診断の型は変えない**(file / pointer / range / code / severity / message)。画像を入力にしたときは、JIN3xx も JIN2xx も
**`.jinscene.json`(ディスク上の JSON)に対して**出す: `file` はその JSON、`pointer` は場面グラフの中の位置(`/bands/3/cells/2` など。
JIN2xx は §3.3 の対応表でモデルの pointer を場面グラフの pointer に写す)、`range` はその JSON テキスト上の位置。画像上の座標は
その pointer の `box` から引く(エディタの重ね描きはこれを使う)。`jin_core.diagnostics` は番号(JIN3xx の集合)だけを知り、画像を知らない。

JIN3xx の一覧は `glyph.md` と `docs/spec/v2/diagnostics.md` に足す(番号帯は 2026-10-03 時点で未使用)。fixture は
`tests/fixtures/errors/scene/JIN3xx_*.jinscene.json` で、今の流儀どおり「その番号をちょうど 1 つだけ出す」。

### 3.6 モード 1(フリーハンド)への伸ばし方

① と ② を「写真全体を Claude に渡し、図形・環・始まりの印の位置を返させる」段に差し替える。③ 以降は変えない。

**S6 で確定(正典 glyph.md §12)**: 入口は型紙と同じで、位置合わせが「型紙なし」を返したらこの経路へ(§9 #46)。Claude には額縁の四隅
(写真)と、正面化した額縁の上の環の形(中心・周の半径・始まりの印・字の大きさ)だけを返させ、升は手元で周に沿った墨の切り分けで出す
(§9 #47 / #49)。③ は塊ごとに字の列を返させる形に変え、④ 以降(構文解析器・診断)は変えない。

### 3.7 外部送信

- 取り込みは写真を Anthropic の API に送る。送るのは `jin check <画像>` / `jin fmt <画像>` / エディタの `POST /read` を明示したときだけ。`--offline` では送らない。送ることを CLI のヘルプと文書に書く
- 認証は `anthropic` SDK の既定の解決順(`ANTHROPIC_API_KEY` ほか)。サーバ側だけで読み、ブラウザに渡さない

## 4. 入口とパッケージ

### 4.1 CLI(サブコマンドは 9 個のまま)

| 呼び方 | 動き |
|---|---|
| `jin check <画像>` | 認識(または `.jinscene.json`)→ 構文解析 → 検査。診断の位置は画像の座標 |
| `jin fmt <画像> --out <x.jin>` | 同じ経路で正準形の `.jin` を書く |
| `jin render <x.jin> --full` | 完全陣(連環陣)を描く |
| `jin render [x.jin] --sheet S\|M` | 印刷用の型紙を描く(x を渡すとその銘文を書き込んだ写し書きの手本・§9 #40) |
| `jin check <写真> [--offline]` / `jin fmt <写真> --out <x.jin> [--offline]` | 型紙の写真(`.jpg` / `.jpeg` / `.webp`)を Claude 認識器で読む。`--offline` は送らない(§9 #37) |
| `jin run` / `jin build` | `.jin` だけを受ける(誤認識したプログラムを確かめずに走らせない・§9 #11) |

画像かどうかは拡張子(`.png` / `.jpg` / `.jpeg` / `.webp`)と `.jinscene.json` で `jin_cli` が見分け、`jin_core.load` より前で `.jin` 相当のテキストにする。`.png` は完全陣の決定的デコーダ、`.jpg` / `.jpeg` / `.webp` は型紙の写真(Claude 認識器)で、PNG は API に送らない(§9 #37)。

### 4.2 パッケージ `jin-glyph`

- 層: `jin-lsp` / `jin-wasmgc` と同じ段の兄弟(layers は `"jin_lsp | jin_wasmgc | jin_glyph"`)。依存は `jin-core` と `jin-render`(幾何の共有)、`Pillow`、`anthropic`
- **import するのは `jin_cli` だけ**(`anthropic` を LSP の起動経路に乗せない)。import-linter と CLAUDE.md の「パッケージを足すときのチェックリスト」8 項目 + 3 か所を全部直す
- モジュール: `scene`(場面グラフの型)/ `parse`(構文解析器)/ `decode`(決定的デコーダ)/ `recognize`(Claude 認識器)/ 等級の幾何。
  **紋の語彙と欄の順は `jin_core.v2.glyph`**(純データ)に置く: レンダラ(`jin_render`)も同じ語彙と欄の順で銘帯を描き、`jin_render` は
  `jin_glyph` を import できない(層の契約)ため(§9 #23)
- 完全陣と型紙の**描画**は `jin_render.v2` に置く(描くのはレンダラ 1 本・`jin_render` の純関数の規律を守る)。清書体の字形も `jin_render` 側に置き、`jin_glyph.decode` はそれを照合に使う。
  清書体は**紋 57 字 + 構造の印 21 字の線の字形**(`jin_render.v2.glyph_paths`。`docs/spec/v2/glyphs/*.svg` はここからの生成物に切り替える)と、
  **ラテン層のドット字形**(ASCII はプレイヤーの 5×7、それ以外は k6x8。`scripts/generate_glyphs.py` が `jin_render` 用の写しも書く・§9 #25)
- 新しい図形の種類で `data-jin-kind` を足すなら、v2 の 13 種の等号テストを契約の変更として更新する

### 4.3 エディタ

- `jin editor` の静的サーバに **`POST /read`** を足す。防御は `POST /run`(ops.md §5.2)と同じ 5 段(`Origin` 検査・カスタムヘッダのトークン・対象の固定・同時 1 本・終了時に残さない)。LSP の `jin/…` は 6 種のまま(§9 #13)
- 流れ: 写真を落とす → 認識 → 図に陣が出る → 写真を下敷きに診断を重ねる → 実行パネルで動く
- **書き出し先**: 開いている `.jin` と同じディレクトリ(`jin editor` の root)に、写真・`<写真名>.jinscene.json`・`<写真名>.jin` を書き、その `.jin` を開き直す。
  既にある名前には書かない(`O_EXCL`)・symlink を拒む・root の外へ出ない(`jin/save` と同じ規律)。HTTP の口がファイルを書く能力を持つので、
  この 3 つを 5 段の防御に加えて `docs/spec/ops.md` §5.2 に書く
- 取り込み後の正本は `.jin`。写真は下敷き(描き直したら撮り直して取り込み直す)

## 9. 決定事項

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 画像の位置づけ | `.jin` と並ぶ 2 つ目の直列化。`.jin` と Pydantic は正本のまま | 実行系・LSP・エディタ・プレイヤーに波及させない |
| 2 | 「全情報」の確かめ方 | Jin の描いた画像についての往復バイト一致を契約にする。手描きは `jin check` を通ればよい | 機械で確かめられ、ネットワーク無しで CI が回る |
| 3 | 1 枚に収める範囲 | `description` は小さな銘帯で載せる。asset と `agent.file` はパスだけ | 例外なく「全情報」と言える。素材の中身と別ファイルの陣は画像に入らない |
| 4 | 紙の前提 | 目標はフリーハンド(モード 1)。印刷した型紙に描くモード 2 から実現する | 座標の基準・順序・升目を型紙が与え、認識が安定する。場面グラフ以降を共通にして 1 へ伸ばす |
| 5 | 認識器 | Claude の視覚モデル(API) | 手書きの字に強く、モード 1 へ伸ばせる。学習データを集めずに済む |
| 6 | 銘文の文字 | 折衷: 名前と数字はラテン文字、演算子・構造は式紋 | Claude は初見の字形に弱い。自由に現れる式紋を 36 字に絞り、残りは枠の決まった判別の紋にすれば形を大きく変えられ、世界観も出る |
| 7 | 式の表し方 | 式紋を交えた中置の一行(式の木を図形にしない) | 手で書ける。既存の `expr` 構文解析と正準化をそのまま使える |
| 8 | 手描きの規模 | fib〜clicker 規模。大きなものは Jin が描いた陣を読む | 手描きの升 5 mm で A3 に約 900 升(見積もり) |
| 9 | 額縁 | 正方形を保つ | 既存の座標系(R = 1)と魔法陣の見た目 |
| 10 | 型紙の等級 | S と M の 2 つから | 認識器が幾何を知るため等級は有限にする |
| 11 | CLI | サブコマンドは増やさない。画像は `check` / `fmt` だけが受け、`run` / `build` は `.jin` だけ | 9 個の契約。誤認識を確かめずに走らせない |
| 12 | 取り込み後の正本 | `.jin`。写真は下敷き | 画像の差分編集を作らない |
| 13 | エディタの取り込み口 | `jin editor` の `POST /read`(`POST /run` と同じ防御) | API キーをブラウザに渡さない。`jin/…` を 6 種のまま保つ |
| 14 | 認識結果の扱い | 写真の隣の `.jinscene.json` に保存し、sha256 が合えば再利用 | 2 回目以降を決定的・無料にし、手で直せて fixture にもなる |
| 15 | 絵の文法の診断 | 新しい番号帯 JIN3xx | 位置が画像の座標で、JSON の位置を持つ JIN0xx / JIN2xx と性質が違う |
| 16 | 外部送信 | 明示したときだけ。`--offline` を持つ | 写真が外へ出ることを利用者が選べるようにする |
| 17 | S0 の合格線 | 認識後の手直しが升数の 2% 以内で `jin check` を通る | 結果を見てから目標を置かないため先に決める。エディタで数升を直すのは許容でき、それ以上だと手で打つ方が早い(仮の値。S0 で外れたら理由を残して改める) |
| 18 | `$schema` | 額縁の正典の印で表す(標準の URL は印だけ、他は全文) | examples-v2 と v2-programs の 19 本はすべて標準の URL を持ち、無いと往復が 1 本も一致しない |
| 19 | 省略できる欄・種別の見分け | 判別の紋 21 字を決まった枠にだけ置く | 式 1 本の銘帯からは `while` と `count` などを区別できない。枠を決めれば認識は少数の候補からの選択になる |
| 20 | 画像入力の診断の位置 | 診断の型を変えず、`.jinscene.json` に対して出す | 要件書 §5 の診断の形と LSP の位置変換をそのまま使える。画像の座標は場面グラフの `box` から引ける |
| 21 | エディタの書き出し | 開いている `.jin` のディレクトリに写真・場面グラフ・`.jin` を書く。既存の名前は拒む | `jin/open` で開き直せる場所に置く。上書きで手元の `.jin` を失わない |
