# Jin 鑑賞ページ(stage)— 召喚の窓(魔法の出力)と音 設計

> 仕様書 ②(全 2 本)。① は `docs/superpowers/specs/2026-10-01-jin-stage-gem-worldview-design.md`(宝玉と金細工の世界観)。
> 旧設計 `docs/superpowers/specs/2026-09-17-jin-stage-design.md` §0 の「第 2 段階」(発動した魔法 = ゲーム画面を
> 「召喚された像」として陣と合成する。音もここで扱う)を実現する。① の前提(配置は SVG・決定性・語彙 4 語)をすべて引き継ぐ。

## 0. 目的・スコープ・非目標

### 目的

世界観「魔法陣 = プログラム、詠唱 = 入力、**魔法 = 出力**」の最後の 1 つを見せる。陣が発動して呼び出したものとして、
ゲーム画面(トレースの `frame` 行の表示リスト)を陣の上空の「召喚の窓」に映し、鳴った音を動画にも入れる。

### スコープ

- 召喚の窓: 置き場所・画面の描き方・縁と枠・開閉(§1)
- 鑑賞ページへ渡すデータ(`stageSize` の欄)と、プレイヤーの描画と字形の写し(§2)
- 音: 合成・プレビュー・書き出しの音声トラック(§3)

### 非目標

- 絵の素材(`sprite`)と音の素材(`play`)の再現(素材のファイルは鑑賞ページに届かない。代わりの印と縁の光で示す)
- 窓の画面の質感の演出(走査線・光の点など。人間の選択でドットのまま)
- 窓を陣と別の場所に置く構図の切り替え
- 新しい依存(three 0.186.0 / mediabunny 1.57.0 のまま)

### 継承する設計前提(変えない)

- **鑑賞ページはプレイヤーのコードもリポジトリのファイルも読まない**(`schemas/` の例外も無い)。apps 同士は import しない
- **決定性**: 絵と音は「トレース行・名前の表・SVG・時刻 `t`・構図・縦横比・書き出しの範囲と速度」だけで決まる。
  `src/` のうち `main.ts` 以外で `Math.random` / `Date.now` / `performance.now` / `new Date(` を使わない
- エディタとの語彙は 4 語(`stage.scene` / `stage.trace` / `stage.status` / `stage.file`)。欄を足すのは可
- ① の色の意味体系(描く力 `canvas` = サファイア、音 `audio` = アメジスト …)

## 1. 召喚の窓

### 1.1 置き場所と大きさ

| 値 | 初期値 |
|---|---|
| 位置 | 陣の核の真上・高さは陣の外周の約 1 倍。カメラから見て陣の少し奥に寄せ、陣の中心と重ならない |
| 向き | 常にカメラを向く(ビルボード) |
| 幅 | 陣の外周の約 0.9 倍。高さは舞台の縦横比(`stageSize`)から |
| カメラ | 窓を収めるため、陣を収める半径を 1.45 → 1.75 に広げる(窓があるときだけ) |

値はすべて初期値で、目視で詰めて stage.md §7 に残す。

### 1.2 画面

- 時刻 `t` の tick(`floor(t)`)以前で最新の `frame` 行の `ops` を、裏の 2D キャンバスに論理解像度の整数倍(初期値 4 倍)で描く。
  テクスチャは補間しない(`NearestFilter`・ドットのまま)
- 板は光源の影響を受けず(`MeshBasicMaterial`)、トーンマップを通さない(`toneMapped: false`)。ゲームの色を正確に見せる。
  白い部分はブルームで少し滲む
- 描く命令は canvas / ui の 9 つ(`clear` / `ink` / `rect` / `circle` / `line` / `text` / `sprite` / `label` / `button`)。
  `sprite` は素材が届かないので、その位置に 6×6 の菱形の印(サファイアの色)を描く

### 1.3 縁と枠

- 窓の周りに root の地金(① §2.3)の細い金細工の枠
- 縁は描く力の宝玉 = サファイアの光。その tick に `tone` が鳴ると縁がアメジストで脈打ち、`play` は縁が一瞬白く光る
- 実行時エラー(`error` 行)の後は、縁がガーネットで明滅し、画面は最後のコマで止まる

### 1.4 開く・閉じる

| きっかけ | 動き | 長さ(初期値) |
|---|---|---|
| root の陣の `enter` | 核から細い光が立ち上がり、窓が開く(幅と高さが 0 → 1) | 0.8 秒 |
| root の陣の `exit` / `finish` | 窓が核へ吸い込まれるように閉じる | 0.8 秒 |
| 最初の `frame` 行より前 | 窓を出さない | — |

root の陣は名前の表の `isRoot`(①)で見分ける。`isRoot` の無い表では、最初の `frame` 行で開き、閉じない。

## 2. データと描画の写し

### 2.1 鑑賞ページへ渡すもの

`stage.scene` に `stageSize: { width: number; height: number }` を足す(エディタの `StagePanel` がモデルの `stage` から渡す)。
欄が無い・形が違う場合は**窓を出さず陣だけを描く**(例外を投げない)。画面の中身と音は既に届く `frame` 行から読む。

### 2.2 写しのファイル(`apps/stage/src/screen/`)

| ファイル | 役割 | 写しの守り方 |
|---|---|---|
| `glyphs.ts` | 非 ASCII の字形(k6x8ゴシック・7001 字) | `scripts/generate_glyphs.py` がプレイヤーと同じ内容を 2 か所に書く。`--check` は 2 か所とも見る。CI の player ジョブの `--stdout \| diff` に stage の分も足す |
| `font.ts` | ASCII の 5×7 | プレイヤーの `apps/player/src/font.ts` とバイト一致(契約テスト) |
| `draw.ts` | `ops` → 2D キャンバス | 扱う命令の名前の集合が `schemas/abilities.json` の canvas と ui の描く命令と等しい(契約テスト。鑑賞ページは `abilities.json` を読まないので名前は書き写す) |
| `frames.ts` | 時刻 `t` に映す `frame` 行・鳴らす音・窓の開閉の進みを選ぶ純関数 | vitest |
| `sound.ts` | `tone` の PCM 合成(§3) | vitest |

窓の描画は `render/summonWindow.ts`(板・枠・縁の光・開閉)。`frames.ts` / `sound.ts` は three を import しない。

### 2.3 画素一致による写しの検査

- 表示リストの fixture: 全 9 命令を含む `tests/fixtures/screen/all-ops.json` と、tetris の数コマ(`tests/fixtures/screen/tetris-*.json`)
- 正解の PNG(`tests/fixtures/screen/*.png`)はプレイヤーの描画で作る。プレイヤーの e2e が自分の描画と正解の画素一致を見る
- 鑑賞ページの e2e が `draw.ts` で同じ `ops` を描き、同じ正解と画素一致を見る

両方のアプリが同じ正解と比べるので、片方だけが変わると落ちる。正解を作り直すときは、プレイヤーの e2e の更新の手順で作る。

## 3. 音

### 3.1 合成(`screen/sound.ts`)

- `frame` 行の `audio` のうち `tone(hz, ms)` を、プレイヤーと同じ矩形波・音量 0.08 で合成する
- 書き出しの範囲(開始〜終了の tick)と速度から、48kHz・モノラルの PCM(`Float32Array`)を作る
- 音の置き場所は `(tick − 開始) / fps / 速度` 秒。0.5 倍速では音程と長さはそのままで、鳴る間隔だけが延びる
- 同時の音は足して [−1, 1] に収める
- プレイヤーとの差は 1 つだけ: 音の頭と終わりに 5ms のフェード(雑音を消すため・書き出しの音質だけの差で決定性に影響しない)
- `play(name)` は鳴らさない(素材が届かない)。`hz ≤ 0` / `ms ≤ 0` はプレイヤーと同じく鳴らさない

### 3.2 プレビュー

- 再生ボタンで走らせている間だけ、各 tick の `tone` を WebAudio で鳴らす(プレイヤーと同じ鳴らし方)。再生ボタンの操作で音を解禁する
- スクラブ中は鳴らさない。音の入り切りのボタン(既定は入り)。`AudioContext` が無い環境では何もしない

### 3.3 書き出し

- 動画に音声トラックを付ける。MP4 は AAC、WebM は Opus
- 音声のコーデックが使えなければ無音の動画を書き出し、`stage.status` の表示に 1 行知らせる(書き出しは止めない)
- Mediabunny 1.57.0 の音声トラックの追加と WebCodecs の `AudioEncoder`(`aac` / `opus`)の可否は、実装の最初に
  `delivery/<最新の *-jin>/stage-api-probe.md` に実測を残してから使う

## 4. テストと証拠

### 4.1 契約

- 決定性の走査(`src/` 全体のまま)が `screen/` にも効く
- `screen/glyphs.ts` の生成物のずれ(`generate_glyphs.py --check`)・`screen/font.ts` とプレイヤーの `font.ts` のバイト一致・
  `draw.ts` の命令の集合と `abilities.json` の等号
- 既存の契約(語彙 4 語・鑑賞ページはリポジトリを読まない・three と mediabunny は stage だけ)は変えない

### 4.2 単体テスト(vitest)

- `frames.ts`: tick の境目・最初の `frame` より前は無し・`error` の後は最後のコマで止まる・開閉の進み(`isRoot` の有無)
- `sound.ts`: `tone` の置き場所と長さのサンプル数・同時の音の合算と収め・0.5 倍速・フェード・決定性
- エディタの `StagePanel`: `stageSize` を `stage.scene` に載せる

### 4.3 e2e

- 画素一致(§2.3)をプレイヤーと鑑賞ページの両方で
- tetris の場面で窓の領域に盤面の色の画素がある
- 書き出した MP4 を読み戻すと音声トラックがあり、長さが映像とほぼ同じ
- `stageSize` の無い場面で窓が出ず、`stage.status.error` が null

### 4.4 変異の実測(`delivery/…/stage-mutations/`)

`draw.ts` の命令を 1 つ描かない / 字形の写しを 1 字ずらす / 音の置き場所に速度を掛けない / `frame` 行を最新ではなく最古から選ぶ。

## 6. 実装の順序

1. probe: Mediabunny の音声トラックと `AudioEncoder`(`aac` / `opus`)
2. 字形の生成先を 2 か所に・`font.ts` の写し・契約テスト
3. `draw.ts` と画素一致の検査(プレイヤーの正解の PNG・両方の e2e)
4. `stageSize` の欄(エディタ・`messages.ts`)
5. `frames.ts` と `render/summonWindow.ts`(窓・枠・縁・開閉・カメラの半径)
6. `sound.ts`・プレビュー・書き出しの音声トラック
7. dev.html・e2e・変異・文書・見てもらう動画(音つき)

## 7. 決定事項表

| # | 決めたこと | 理由 |
|---|---|---|
| 1 | 像は陣の上空の「召喚の窓」(ビルボード) | 陣が呼び出したものとして見せ、どの構図でも画面が読める(人間の選択) |
| 2 | 画面はドットのまま光の窓に映す | ゲームの中身と文字が最も読める(人間の選択) |
| 3 | 音は書き出しにも入れ、プレビューでも鳴らす | 共有する動画に音を残す(人間の選択) |
| 4 | 描画は写し + 字形は生成器が 2 か所に書く(案 A) | 依存の規則(apps 同士は import しない・stage は何も読まない)を変えずに済む(人間の選択) |
| 5 | 写しのずれは画素一致で捕まえる | プレイヤーと鑑賞ページが同じ正解の PNG と比べれば、片方だけの変更が落ちる |
| 6 | `stageSize` を `stage.scene` の欄で渡し、無ければ窓を出さない | 舞台の大きさは SVG にも名前の表にも無い。① と同じく fail-soft |
| 7 | `sprite` は印、`play` は縁の光で代える | 素材のファイルは鑑賞ページに届かず、読ませると「何も読まない」原則に反する |
| 8 | 縁の色は描く力(サファイア)と音(アメジスト)で意味を持たせる | ① の色の意味体系を窓にも通す |
| 9 | 音の頭と終わりに 5ms のフェードを足す | 書き出しの雑音を消す。トレースと決定性には影響しない |
| 10 | 音声のコーデックが無ければ無音で書き出す | 書き出し自体を止めない(fail-soft) |
