# Jin 鑑賞ページ(stage)— 宝玉と金細工の世界観と演出の全量 設計

> 仕様書 ①(全 2 本)。② は「召喚された像」(トレースの `frame` 行の表示リストを陣の上に合成する。
> 旧設計書 §0 の「第 2 段階」)で、この設計の確認の後に別に書く。
> 置き換える旧設計: `docs/superpowers/specs/2026-09-17-jin-stage-design.md` の §2.1(素材と光)・§2.3(演出の見え方)。
> それ以外(構成・データの流れ・書き出し・語彙・カメラの構図)は旧設計のまま。

## 0. 目的・スコープ・非目標

### 目的

鑑賞ページの魔法陣を、**意味を色で読める多彩な作品**にする。旧設計の「金一色 + 警告の赤だけ」をやめ、
「金細工の陣に宝玉がはめ込まれ、発動するとその力の宝玉が灯り、光が宝玉の色で走る」という世界観に作り直す。
色は飾りではなく**意味**を運ぶ(何の力か・何の値か・どの陣か)。何が起きたかは**動き**で表す。

### スコープ

- 色の意味体系(力の宝玉・記憶の型の宝玉・陣の地金)と、それを描く宝玉と金細工の立体
- トレースの 13 種の kind の動きの全量、常に動く飾り、トレースから決まるカメラの演出
- 3D エフェクト(床の反射・ゴッドレイ・被写界深度・色収差 / ビネット / グレイン・光の柱・刻印の文字・天球儀の輪・粒子の 1 系統)
- 名前の表に欄を 2 つ足す(エディタの `names.ts`)
- **まず全部入りを動かして見る**: プレビューも書き出しも最高品質で描き、品質の切り替えは作らない

### 非目標

- 召喚された像(仕様書 ② に分ける)
- 品質の切り替え・軽量モード(動かして重さを測ってから別に設計する)
- 新しい依存(pmndrs の `postprocessing` / WebGPU は入れない。three 0.186.0 と mediabunny 1.57.0 のまま)
- `.jin` への見せ方の語彙の追加、v1 の陣の 3D 化、GIF 書き出し(旧設計の非目標のまま)

### 継承する設計前提(変えない)

- **配置は SVG からだけ取る**。宝玉の位置も要素の中心から取り、座標を計算し直さない
- **決定性**: 絵は「トレース行・名前の表・SVG・時刻 `t`・構図・縦横比」だけで決まる。乱数は `seq` を種にした mulberry32。
  `src/` のうち `main.ts` 以外で `Math.random` / `Date.now` / `performance.now` / `new Date(` を使わない
- エディタとの語彙は 4 語(`stage.scene` / `stage.trace` / `stage.status` / `stage.file`)。欄を足すのは可
- three と mediabunny は `apps/stage` にだけある。エディタは線を描かない
- 慣れの規則(stage.md §3.2: 毎 tick 続く発火はうなりに落とす)

## 1. 世界観

| 要素 | 意味 |
|---|---|
| 金細工(輪・線・手順の小円・額縁) | 器。陣の構造そのもの。陣ごとに地金が違う |
| 宝玉 | 力と値。陣の要素にはめ込まれ、発動で内側から灯る |
| 光 | 流れ。宝玉の色で走る(呼んだ力の色・書いた値の色) |
| 動き | 何が起きたか(起動・呼び出し・代入・放出・完了・警告…) |

背景は宝玉の色が映えるほぼ黒の深い藍 `#05060c`。霧は藍の薄い霞、漂う粒子は金と宝玉の色の混ざった火の粉と塵。

## 2. 色の体系(4 軸)

色の値はすべて**初期値**で、動かして見てから詰め、確定値を stage.md §7 に根拠つきで残す。

### 2.1 軸 A: 力の宝玉

`cast` の光線・紋の宝玉・火花の色。`cast` の `name` の `.` の前を名前の表の `sigilKinds` で引いて決める。

| 力 | 宝玉 | 色 | 屈折率 |
|---|---|---|---|
| `canvas` | サファイア | `#2f6bff` | 1.77 |
| `input` | エメラルド | `#1fd47a` | 1.58 |
| `ui` | ペリドット | `#a8e83a` | 1.67 |
| `audio` | アメジスト | `#a05cff` | 1.54 |
| `random` | オパール | 遊色(色相が時刻と `seq` で巡る) | 1.45 |
| `storage` | 琥珀 | `#ffa62b` | 1.54 |
| `agent` | ムーンストーン | `#cfe3ff`(乳光) | 1.52 |
| 自陣の手順 / `summon` | 金 | `#ffd27a` | — |
| `transfer` / 委譲 | トパーズ | `#ff8a3d` | 1.62 |
| `emit` | ダイヤモンド | `#ffffff` + 分光 | 2.42 |
| `assert` | ルビー | `#ff2a4a` | 1.77 |
| `error` | ガーネット | `#b0102a` | 1.79 |

### 2.2 軸 B: 記憶の型の宝玉

記憶の四角にはめる宝玉と、`set` の光の色。`set` の `name` を名前の表の `stateTypes` で引いて決める。

| 型 | 宝玉 | 色 |
|---|---|---|
| `num` | シトリン | `#ffc83a` |
| `str` | アクアマリン | `#5fd8e8` |
| `bool` | 真珠 / 黒オニキス | 値が真なら `#f4f0e8`(白い光)、偽なら `#14141a` の地に銀 `#c8ccd8` の光 |
| `list<…>` | トルマリン | `#3ad08a` → `#ff7aa8` のグラデーション |
| 型紙(上記以外の名前) | スピネル | `#ff3a7a` |

### 2.3 軸 C: 陣の地金

陣を pointer `/circles/i` の i(`circles` の並び順)で巡らせる。root は並び順によらず常にイエローゴールド。
root 以外は i の小さい順に、ローズゴールドから巡らせる。

| 順 | 地金 | 色 | 粗さ |
|---|---|---|---|
| root | イエローゴールド | `#d4a24a` | 0.3 |
| 1 | ローズゴールド | `#d68a6e` | 0.32 |
| 2 | ホワイトゴールド | `#d8d4c8` | 0.28 |
| 3 | プラチナ | `#b8bcc4` | 0.24 |
| 4 以降 | 1 から繰り返す | | |

陣に属さない額縁(`stage` / `form`)は root の地金。

### 2.4 軸 E: 動き

「何が起きたか」は色で表さず、§5 の動きで表す。同じ色でも動きで区別できることを設計の条件にする。

### 2.5 引けないとき

`sigilKinds` / `stateTypes` の欄が無い、名前が引けない、型の文字列が読めない場合は、**例外を投げず金で描く**。
古いエディタから届いた場面は金一色で見える(旧設計の見え方に近い)。

## 3. 宝玉の配置と素材

### 3.1 置き場所

位置は SVG の要素の中心(層の高さは旧設計の 6 層のまま)。

| SVG の要素(`data-jin-kind`) | 置くもの | 色 |
|---|---|---|
| `sigil` | 半球に磨いた宝玉(カボション) | 軸 A。`summon` は金、`agent` はムーンストーン |
| `state` | 角を面取りした宝玉(ステップカット) | 軸 B |
| `core` | 陣で最大のブリリアントカットの透明な宝玉(ダイヤ) | 普段は無色。発動した力の色を映す |
| `on` | 菱形の水晶 | 無色。届いたイベントの色に染まる |
| `guard` | 三角のルビー | 普段は暗く沈み、`assert` で灯る |
| `delegate` | 小粒のトパーズ | 軸 A のトパーズ |
| 輪・線・手順の小円・額縁・`flow-edge`・`step`・`step-edge` | 金細工 | 軸 C |

宝玉の大きさは要素の SVG 上の大きさ(外接円の半径)に比例させる。比は実装で目視して決める。

### 3.2 素材

- 宝玉は `MeshPhysicalMaterial`: `transmission`・`ior`(§2.1 の屈折率)・`dispersion`・`thickness`・`attenuationColor`(宝玉の色)・
  `clearcoat`。灯ると自発光を上げ、宝玉の中心に加算の光のスプライトを置いて「内側から光る」ように見せる
- 金細工は `MeshStandardMaterial`(`metalness` 1)を地金ごとの色と粗さで。環境マップは今の `RoomEnvironment` の PMREM
- 光源は今の主光源・補助光・環境光の構成を残し、色と強さは藍の背景に合わせて詰め直す

## 4. データ: 名前の表に足す欄

エディタの `apps/editor/src/stage/names.ts`(`buildStageNames`)が、`jin/model` の JSON から陣ごとに次を足して
`stage.scene` の `names` に載せる。語彙の数は変わらない。

```ts
interface CircleNames {
	readonly pointer: string;
	readonly sigils: Readonly<Record<string, string>>;
	readonly state: Readonly<Record<string, string>>;
	readonly delegates: Readonly<Record<string, string>>;
	readonly sigilKinds: Readonly<Record<string, string>>; // 新: sigil 名 → host の名前空間名 / "summon" / "agent"
	readonly stateTypes: Readonly<Record<string, string>>; // 新: state 名 → 型の文字列("num" / "list<num>" / 型紙名 …)
}
```

- `sigilKinds` は `kind == "host"` なら `host` の値(名前空間名)、それ以外は `kind` の値
- `stateTypes` は state の `type` をそのまま(解釈は stage の `palette.ts` が §2.2 の表で行う)
- 地金は stage が pointer の i から決める(欄は足さない)
- stage の `messages.ts` は 2 つの欄を**任意**として受ける(無ければ空の表。§2.5)

## 5. 動きの全量

すべて「トレース + 時刻 `t` → 場面」の関数。演出の名前・強さ(`once` / `habit`)・慣れの規則は stage.md §3 のまま残し、
見え方を次で置き換える。演出ごとの長さと包絡は stage.md §3.3 の表を置き換えて正典にする(初期値は §5.4)。

### 5.1 13 種の kind

| kind | 演出 | 動き |
|---|---|---|
| `enter` | `ignite` | 核の宝玉から光が外へ環を 1 つずつ駆け上がり、層が下から順に浮き上がって所定の高さに収まる。宝玉がその順に点火し、最後に陣全体が一度息づく |
| `exit` | `fade` | 外周から核へ光が引き、層が沈み、宝玉が外側から順に消える |
| `event` | `chant` | 外の空間から粒子が渦を描いて境界環の ◇ に吸い込まれ、◇ がイベントの色に染まる(`key` / `pointer` はエメラルド、`message` は `emit` と同じダイヤの白、`tick` / `exit` は金) |
| `rite` | `spin` | 手順の小円が金に点灯し、一回転しながら小さな紋を宙に浮かべて消える |
| `cast` | `beam` | 手順の小円から呼んだ力の宝玉へ光の粒が**弧を描いて走り**、着いた宝玉が共鳴して床に広がる光の輪(波紋)を出す。色は軸 A |
| `set` | `flash` | 記憶の四角の輪郭を型の宝玉の色の光が一周し、宝玉がきらめく(値が変わったときだけ強い) |
| `emit` | `release` | 核からダイヤの白い光が境界環の外へ放射状に放たれ、分光した虹の粒子が散る |
| `transfer` | `flow` | 手順からトパーズの太い光の流れが委譲の小円へ注ぎ込み、小円が満ちる |
| `wait` | `breathe` | 手順の小円の光が呼吸するように弱まり、周りに砂時計の砂のような粒子が細く落ちる(`resume` の行は光らせない) |
| `finish` | `crown` | 陣全体が強く輝き、核から天へ**光の柱**が立ち、全宝玉の色の火の粉が噴き上がって静まる |
| `assert` | `warn` | △ のルビーが赤く脈打ち、陣の上を赤い警告の環が一度走る |
| `error` | `crack` | 輪に亀裂状のガーネットの光が走り、宝玉が順に暗転し、陣が少し傾いて沈む |
| `frame` | `pulse`(新) | tick の拍。外周の金細工がごく弱く脈打つ(強さ `beat` = 常に 0.1・慣れの対象外・光線も火花も出さない) |

`frame` は旧設計では「光らせない」だった。`pulse` は陣の鼓動であって発動の演出ではないので、`frame` 行の `circle` が null でも
root の外周だけを脈打たせる。

### 5.2 常に動くもの(意味を持たない飾り)

- 輪の外の目盛りの逆回転(今のまま)
- 各層の金細工のごく遅い自転(層の偶奇で向きが逆)。**宝玉と光線の端点も同じ回転で動かす**(ずれない)。
  回転の中心は陣の中心(SVG の陣の `<g>` の中心)
- 天球儀の輪(§6)・漂う粒子・宝玉のきらめき(屈折と分散がカメラと光源の動きで揺れる)

### 5.3 カメラの演出

構図(俯瞰 / 斜め 45° / 低い煽り)と周回・手の足し分は旧設計のまま。その上にトレースから決まる足し分を重ねる。

| kind | カメラ |
|---|---|
| `enter` | 2.4 秒かけて距離を 0.9 倍まで寄せて戻す |
| `finish` | 光の柱を追って仰角を +8° して戻す |
| `error` | 0.4 秒の小さな揺れ(振幅と位相は `seq` の mulberry32) |

同じ時刻に複数あれば足し合わせ、仰角は 5°〜89° に収める。

### 5.4 長さ(秒)の初期値

`ignite` 2.4 / `fade` 1.6 / `chant` 1.0 / `spin` 0.9 / `beam` 0.8 / `flash` 0.8 / `release` 1.4 / `flow` 1.2 / `breathe` 1.5 /
`crown` 3.2 / `warn` 1.4 / `crack` 2.0 / `pulse` 0.5。包絡は stage.md §3.3 の形(立ち上がり 15%)を既定とし、
動きが包絡と別の進み(弧の上の位置・柱の伸び・層の高さ)を持つものは、進み `p` から直接求める。

## 6. 3D エフェクトと後処理

| 効果 | 作り方 |
|---|---|
| 床の反射と投影 | 陣の下(層 0 よりさらに下)に暗い磨いた床。three の `Reflector` で陣と光を映す。波紋・光の輪は床の上の加算の円盤 |
| ゴッドレイ | 核の画面上の位置から放射状にぼかす自前の ShaderPass。濃さは灯った宝玉の強さの和 |
| 被写界深度 | `BokehPass`。焦点は陣の中心 |
| 色収差・ビネット・グレイン | 1 つの自前の ShaderPass。グレインの乱れは時刻 `t` から作る |
| ブルーム | 今の `UnrealBloomPass`。宝玉の発光に合わせて値を詰め直す |
| 光の柱 | `finish` で核から天へ伸びる加算の円柱。上へ流れる帯をシェーダで描く |
| 刻印の文字 | 今の文字テクスチャから法線と凹凸を作り、金の板に彫った刻印として描く(書体のファイルを持ち込まない・日本語の名前も描ける) |
| 天球儀の輪 | 境界環の外に、意味を持たない飾りの輪を 2 本。傾けて回す。陣の要素は傾けない |
| 粒子 | 火花・火の粉・吸い込み・虹の粒・砂を `InstancedMesh` + 自前のシェーダの 1 系統にまとめる(上限 4096) |

後処理の順序: 描画 → 被写界深度 → ゴッドレイ → ブルーム → 色収差・ビネット・グレイン → 出力(トーンマップ)。

使う three の部品(`Reflector` / `BokehPass` / `ShaderPass` / `MeshPhysicalMaterial` の `dispersion` / `InstancedMesh`)は、
実装の最初に `delivery/…/stage-api-probe.md` に 0.186.0 での実測を追記してから使う(API を記憶で書かない)。

## 7. 構成

`apps/stage/src/render/` を役割で分ける。

| ファイル | 役割 |
|---|---|
| `palette.ts` | 力の宝玉・型の宝玉・地金の表と、行 → 色の選び方(純関数・three に依存しない) |
| `gems.ts` | 宝玉の形(カボション / ステップカット / ブリリアント / 菱形 / 三角)と素材 |
| `gilded.ts` | 金細工(地金ごとの素材に拡張)・刻印の文字 |
| `motion.ts` | 層の浮き沈み・自転・天球儀・カメラの足し分など、時刻から決まる形の変化(純関数) |
| `glowView.ts` | 光・光線(弧)・宝玉の点灯・波紋・光の柱の駆動 |
| `particles.ts` | 粒子の 1 系統 |
| `floor.ts` / `pillar.ts` | 床と光の柱 |
| `post.ts` | 後処理のパスの組み立て(ゴッドレイと仕上げのシェーダを含む) |
| `stageRenderer.ts` | 上を組み立てる |

`effects.ts`(トレースから発火と強さを求める)は描画から独立した純関数のまま拡張する(`pulse` と、発火ごとの色の鍵)。
`palette.ts` と `motion.ts` も three を import しない純関数にして、vitest で WebGL 無しに試せるようにする。

## 8. 決定性

- グレイン・遊色・粒子の散り方・カメラの揺れは、時刻 `t` と `seq` の mulberry32 だけから作る
- 新しいファイルも `Math.random` / `Date.now` / `performance.now` / `new Date(` の走査の対象(契約テストの走査範囲は `src/` 全体のまま)
- 保証は旧設計と同じく**場面の列**まで。GPU とブラウザの違いによるピクセルの差は保証しない

## 9. テストと証拠

### 9.1 正典の表と実装の等号

stage.md に machine-readable の表を新設する: `stage-gems`(§2.1)・`stage-state-gems`(§2.2)・`stage-metals`(§2.3)。
`stage-effects` は `frame` の行を `pulse` / `habit` 以外の強さ(`beat`)に直す。`tests/spec/test_stage_spec_consistency.py` と
`tests/contract/test_stage_contract.py` が `palette.ts` / `effects.ts` の表と突き合わせる。

### 9.2 単体テスト(vitest)

- `apps/editor/test/`: `buildStageNames` が tetris / othello のモデルから `sigilKinds` / `stateTypes` を出す
- `apps/stage/test/palette.test.ts`: 行(`cast canvas.rect` / `cast random.range` / `set score` / `set board` / `transfer` / `emit` /
  `assert`)→ 宝玉 → 色。欄が無い・引けないときは金。root と並び順から地金
- `apps/stage/test/motion.test.ts`: kind ごとの時刻の関数(層の高さ・弧の上の位置・柱の伸び・カメラの足し分)の端点と単調性。
  自転で宝玉と光線の端点が同じ角だけ回る
- `apps/stage/test/effects.test.ts`: 今のテスト(慣れの規則)を残し、`pulse` を足す
- `apps/stage/test/messages.test.ts`: 新しい欄があってもなくても `stage.scene` を受ける

### 9.3 e2e(Playwright の Chromium)

- 今の「PNG と 1 秒の動画を書き出して読み戻す」を新しい描画で通す
- 色の粗い検査: `cast canvas.*` が光る時刻の PNG に、サファイアの色相(H 210°〜235°・S と V が一定以上)の画素が一定数ある

### 9.4 目視と変異

- `apps/stage/dev.html` に kind ごとに発火させる切り替えと、fixture(paddle / tetris / othello)の選択を足す
- 仕上げに鑑賞モードで tetris の録画を再生して短い動画を書き出し、見てもらう(「動かして見てから検討」の材料)
- `delivery/…/stage-mutations/` に変異を足す: 宝玉の表の入れ替え・`Math.random` の混入・欄が無いときに例外を投げる・

## 12. 決定事項表

| # | 決めたこと | 理由 |
|---|---|---|
| 1 | 世界観は「宝玉と金細工」 | 金の陣を土台に残したまま多彩にでき、宝石の屈折と分散が 3D ならではの見せ場になる(人間の選択) |
| 2 | 色の軸は A(力)+ B(記憶の型)+ C(地金)+ E(動き)。手順ごとの固有色は採らない | 役割を混ぜずに多彩にする。意味を持たない色は A の読み取りを邪魔する(人間の選択) |
| 3 | 旧設計の「金以外は警告の赤だけ」を廃止 | 世界観の作り直し(人間の判断) |
| 4 | three の構成を拡張し、新しい依存を入れない | 土台を変えずに見た目の検討にすぐ入れる(人間の選択) |
| 5 | 品質の切り替えを作らない | まず全部入りを動かして見てから判断する(人間の判断) |
| 6 | 仕様書を ①(世界観と演出)と ②(召喚された像)に分ける | 色と演出は絡み合う。像は描画経路が別(人間の承認) |
| 7 | 地金は pointer の i から stage が決め、欄を足さない | 名前の表に配置以外の情報を増やさない。並び順は `.jin` だけで決まる |
| 8 | 欄が無い・引けないときは金で描く | 旧設計の「引けなければ光らせない」と同じ fail-soft。古いエディタとも動く |
| 9 | `frame` を `pulse`(強さ 0.1 の鼓動)にする | 発動の演出ではなく陣の鼓動として、tick の拍を見せる |
| 10 | 天球儀の輪は飾りとして足し、陣の要素は傾けない | 配置の情報を増やさず、光線の端点もずらさない |
| 11 | 刻印の文字はテクスチャから法線を作る | 書体のファイルを持ち込まず、日本語の名前も描ける |
