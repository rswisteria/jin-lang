# ADR-002: Phase 5〜6 エディタはデザイナー不在下で機能要件限定の最小 UI を AI 仮判断で実装し、デザインは後日差し替える

> ⚠️ **AI 仮決定（ai_provisional）** — auto mode の仮判断であり人間確定ではない（DP-AUTOMODE-01）。PR レビュー後、`/decide` で approved / overridden に確定する。

- **ステータス**: proposed (ai_provisional)
- **日付**: 2026-09-04
- **決定者**: auto-decider
- **関連判断ポイント**: DP-JIN-EDITOR-UX-01

## コンテキスト

jin-requirements.md §11 は「Phase 5 は Xtone の UI/UX の知見を入れる工程なので brainstorming の段階でデザイナーを巻き込む前提でよい」と明記しているが、auto mode にデザイナーは参加しない。一方で依頼者はビジュアルエディタを明示的に発注しており、Phase 5〜6 を本ランのスコープから外せない。参照可能な社内デザインシステムは本セッションでは存在確認できない。

## 選択肢

| 選択肢 | 採否 |
|---|---|
| 機能要件(§7.1 / §7.2)だけを満たす最小 UI を AI 仮判断で作り、デザインは後で差し替える | 採用 |
| Phase 5 を本ランのスコープから外し、デザイナー参加後の別ランにする | 不採用 |
| Xtone の既存デザインシステム/UI ガイドラインを参照して AI が準拠させる | 不採用 |

## 決定

DP-JIN-PHASE-SCOPE-01 で Phase 5〜6 を本ランに含めたため、recommended の「Phase 5 を本ランのスコープから外し、デザイナー参加後の別ランにする」は依頼者が名指しした「ビジュアルエディタ」を成果物から落とすことになり採用できない(requirements-analyst の recommended より依頼者の明示発話を優先)。残る 2 案のうち「Xtone の既存デザインシステム/UI ガイドラインを参照して AI が準拠させる」は、参照すべきデザインシステムが jin-requirements.md にも本リポジトリにも示されておらず本セッションで存在確認できないため根拠にできない(T-002 具体値の捏造禁止)。よって機能要件に限定した最小 UI を採る。要件書 §7.1 / §7.2 は機能要件のみで見た目の具体指定がなく、§0「エディタは LSP から SVG を受け取って表示し、独自に描画しない」・§10 #9「レンダラは Python 1 本」・§10 #10「エディタの状態管理はファイルが唯一の状態。編集は全て jin/applyOps」・§7.1 のフォームは JSON Schema 由来、という既定により手書きデザインの余地が元々小さいことが本案の成立根拠。完了判定は §9「エディタ: Playwright スモーク(開く → 紋を追加 → 保存 → ファイルが期待の正準形になる)」および成功条件 5(モデル→ファイル→モデルが同一、ファイル→モデル→ファイルがバイト同一)とする。adr は handoff.json では false だったが、それは Phase 5 を除外する前提での値であり、Phase 5 を含める判断に転じたことで本 DP は「エディタの UI を誰が決めるか(AI が仮判断で作り、デザイナー参加後に差し替える)」という責務分界の決定になったため true に変更した。confidence は medium — 推奨を不採用とし残り 2 案の比較で選んだため。

## 影響

エディタの UI に関する判断(プロパティパネル・ドラッグ操作・診断バッジ・タイムラインスクラバ)が全て AI 仮判断になり、デザイナー参加時に見た目の作り直しが発生しうる。ロジックとスタイルを分離することで差し替え範囲をスタイル層に限定する。成功条件 5 と §9 の Playwright スモークは本ランで達成対象に含まれる。
